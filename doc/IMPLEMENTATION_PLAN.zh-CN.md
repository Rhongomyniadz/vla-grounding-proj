# 实施计划

[English](IMPLEMENTATION_PLAN.en.md) | [简体中文](IMPLEMENTATION_PLAN.zh-CN.md)

本计划用于实施 [README](../README.md) 中描述的项目，明确预期系统、实验方案、学习职责和完成标准。目前所有实施里程碑均未完成，本文不包含任何已取得实验结果的声明。

具体的分次任务、学习者练习和交接检查见[每周学习计划](../weekly-plan/README.zh-CN.md)。本文仍是架构与实验规格的权威来源。

## 1. 工作方式与职责分工

计划用十二周完成，每周投入十到十五小时，在另一台配备 RTX 5080 的电脑上通过 WSL2 运行。除工程实现和实验外，还要为独立编程及结果解读预留时间。

### 职责分工

| 组件 | 学习者负责 | 编程智能体协助 |
| --- | --- | --- |
| 环境 | 理解环境配置和验证命令 | 依赖锁定、CUDA 与渲染诊断、安装脚本 |
| 模型与仿真器连接层 | 梳理输入、输出及其转换过程 | 库接口集成、相关源码讲解 |
| 单回合推理循环 | 首次编写外层循环 | 提供可用连接层、提示、代码审查和集成检查 |
| 语言实验 | 设计对照条件、编写初始指令、构建实验用例 | 配置校验和执行基础设施 |
| 目标评分 | 定义正确与错误结果，选择目标谓词 | 仿真器集成和终止逻辑审查 |
| 评估指标 | 成功率、配对比较、泛化差距 | 核对计算并协助估计不确定性 |
| 数据准备与 LoRA | 检查样本，说明干预依据 | 数据准备脚本和上游训练接口集成 |
| 实验产物与可视化 | 选择需要解释的证据 | 序列化、视频输出、绘图基础设施 |
| 结论 | 先独立解读结果，提出有证据支持的主张 | 分析混杂因素、提出替代解释、润色表达 |

可大致将 30–40% 的编程工作留给自己，集中在核心学习组件。代码量不作为验收指标。

### 每项功能的工作流程

1. **理解并预测：** 用十五到三十分钟阅读相关概念或源码。在实验前说明输入、输出、预期行为，并提出预测。
2. **实现一个小功能：** 对学习者负责的逻辑，由学习者先尝试实现。智能体提供接口、有针对性的提示和审查。委托工程工作时，要限定任务范围并给出明确验收条件。
3. **检查、解释并修改：** 运行功能，解释关键代码，再独立做一项有实际意义的修改。随后由智能体提供两到三个理解检查问题和一道实践练习。

学习者练习时，智能体可以继续推进不依赖该练习的基础设施工作。常规委托工程工作不需要额外确认。对于学习者负责的组件，除非学习者明确要求接手，否则智能体必须保留其首次实现机会。

每周安排一小时关闭编程智能体独立工作，仍可使用文档、源码、编辑器和终端。下一次协作时，先说明自己的尝试和观察，再请求帮助。

每周可分配两小时学习概念、三到四小时独立实现、两到三小时进行智能体辅助工程工作、两到四小时开展实验，以及一小时复述和规划。通过验证的长时间任务可以无人值守运行。

### 智能体工作要求

- 在实现主要功能前，解释不熟悉的概念和重要设计选择。
- 区分常规集成代码和必须理解的核心逻辑。
- 对模型与评估代码展示真实输入、输出、张量形状和数据流。
- 复用成熟库接口，以小步、可独立验证的方式实现变更。
- 调试时说明根本原因，以及修正为何能解决该原因。
- 不得编造结果，也不得悄悄改变评估条件。
- 遵守已提供的仓库编码、错误处理、文档、测试和提交规则。

## 2. 系统实现

### 环境与可复现性

使用 Python 3.12 和 LeRobot v0.6.1 作为初始基线。统一解析兼容依赖，在目标电脑验证后锁定版本。使用接口前检查固定版本的源码；开发版文档可能描述更新的行为。

基础 LIBERO 和 LIBERO-plus 分别使用独立 Python 环境，因为它们都提供 `libero` 导入命名空间。分别固定仿真器分支版本和资源版本。代码、环境、数据集及资源均放在 WSL 的 Linux 文件系统内，并预留约 100 GB 可用存储。

首次环境检查必须验证：

1. WSL 能访问 GPU，且 PyTorch 能实际执行 CUDA 运算。
2. MuJoCo 能渲染主相机和腕部相机画面。
3. 能加载模型检查点、分词器和处理流水线。
4. 策略输出有限数值的动作，仿真器能正常执行步进。
5. 能写入并播放 MP4 视频。

先使用文档中的 EGL 渲染配置。如无法工作，应明确报错并给出具体诊断，不得悄悄更换渲染后端或电脑。遵循 NVIDIA 的 [WSL 驱动说明](https://docs.nvidia.com/cuda/wsl-user-guide/index.html)，使用 Windows 主机提供的 GPU 驱动。

先测量峰值显存、单次训练更新耗时和单回合耗时，再估算完整实验成本。本项目不包含付费算力或自动上传；关闭自动模型发布和外部实验追踪。

首次正式测量前，将模型、分词器、数据集和资源引用解析为不可变版本。每次实验保存解析后的依赖版本、配置、版本标识、哈希、硬件信息和渲染后端。

### 架构与接口

构建一个小型 Python 包，划分五项职责：

| 职责 | 行为 |
| --- | --- |
| 环境连接层 | 创建仿真、恢复初始状态、执行动作、计算谓词、释放资源 |
| 策略连接层 | 加载检查点与处理流水线、准备观测、重置策略状态、生成动作 |
| 实验执行器 | 执行明确列出的回合清单并保存结果 |
| 数据准备 | 选择示范轨迹、按回合划分数据集、生成指令变体 |
| 分析 | 计算指标、生成图表、导出报告表格 |

复用 LeRobot 的加载逻辑、处理流水线、数据工具、LoRA 支持和训练循环。自定义代码集中处理实验控制。配置、清单、重标注、指标和分析使用强类型、单一职责的函数；仅在外部接口层使用类。

为环境检查、清单准备、评估、数据准备、各训练组训练和分析提供独立命令。命令接收明确的配置或清单路径，不得依赖隐藏的实验设置。

使用结构化记录并在运行时校验必填字段。对外部数据中无关的额外字段可以忽略，但不得削弱必填字段的校验。

| 记录 | 必需信息 |
| --- | --- |
| 实验规格 | 策略版本、后端、任务、指令条件、初始状态、随机种子、回合限制 |
| 回合规格 | 稳定标识、场景、指令、请求目标、初始状态引用、策略采样种子 |
| 回合结果 | 完成状态、请求目标是否成功、首个完成目标、步数、耗时、产物引用 |
| 运行清单 | 解析后的配置、依赖/模型/数据/资源版本、哈希、硬件和渲染信息 |

保存每回合结果、压缩轨迹和执行视频。轨迹必须能够展示观测、指令、预测动作块和实际执行动作，以便检查。CSV 汇总应从已保存结果生成。

使用结构化日志和 `tqdm` 进度指示。网络操作采用次数有限的重试，每次给出警告，最终仍失败时抛出最后一次错误。配置、解码和仿真器错误必须携带上下文并停止运行。超时属于有效的失败回合；基础设施异常表示实验未完成。恢复运行时只执行同一清单中未完成的回合，不产生重复结果。

### 从感知到动作的接口约定

校验两路相机观测、八维机器人状态、分词后的语言及注意力掩码、预测动作块，以及实际执行的七维动作。明确配置相对控制模式、图像分辨率和朝向、预处理、归一化及动作解码。

读取下载检查点中的特征名，在环境键名与策略键名不一致时使用 LeRobot 的显式重命名映射。检查真实张量和内部填充，不能假设所有中间结果都与公开接口具有相同维度。

正式研究保留检查点的动作分块设置。每个回合之间重置策略缓存和动作队列。不同策略之间的预处理、归一化、每次预测后的动作执行步数及解码方式保持一致。

**学习者练习：** 编写单回合外层循环。在独立开发实验中，改变重新请求动作块前执行的预测动作数量，先预测再测量推理频率、耗时和行为变化。未明确修改正式实验配置前，不得将这一探索性改动带入已冻结的主实验。

## 3. 实验方案

### A. 建立基线

先运行一个 LIBERO-Spatial 任务，共三个回合，验证流水线。保存成功与失败视频，梳理从指令到动作的完整路径。

按完整任务名固定四个主要 LIBERO-Object 任务，并记录固定版本基准中解析出的任务 ID：

| 任务名 | 同一场景中的替代目标 |
| --- | --- |
| `pick_up_the_alphabet_soup_and_place_it_in_the_basket` | 奶油奶酪（cream cheese） |
| `pick_up_the_cream_cheese_and_place_it_in_the_basket` | 字母汤罐头（alphabet soup） |
| `pick_up_the_tomato_sauce_and_place_it_in_the_basket` | 黄油（butter） |
| `pick_up_the_butter_and_place_it_in_the_basket` | 番茄酱（tomato sauce） |

在固定版本的任务定义中核实所需物体和目标区域。不得在查看结果后替换表现较差的任务。如果基线持续失败，应先排查接口与执行错误，再扩大实验。

### B. 评估语言行为

每个主要任务预留五个初始状态用于开发，另用二十个不同状态进行最终评估。保存其标识和状态哈希。在不同指令条件和策略之间匹配仿真器初始状态及策略采样种子；只使用相同的环境整数种子并不足够。

最终采用六种条件：

| 条件 | 指令与评分方式 |
| --- | --- |
| 原始指令 | 基准原有表述，评估原始目标 |
| 改写 1 | 留出的词汇变化，评估原始目标 |
| 改写 2 | 留出的句式变化，评估原始目标 |
| 改写 3 | 留出的上下文表述变化，评估原始目标 |
| 改变目标 | 请求配对的替代物体，评估替代目标 |
| 空指令 | 空任务内容经过正常分词流程，针对原始目标进行诊断性评分 |

初始指令由学习者编写，并解释为何语义等价。微调前固定互相独立的训练、验证和最终测试模板。确认目标物体和放置位置表达明确，并且分词后不会因截断而丢失。

改变目标的实验必须保持物理场景不变，只修改传给策略的指令。使用 LIBERO 现有谓词评估请求的替代目标。完成原始目标不得导致替代目标回合提前结束。同时记录最终是否完成请求目标，以及首个被放入篮子的物体；同时满足多个目标的模糊情况也必须记录。

不得通过切换到另一个基准任务来代替此对照，因为干扰物和布局可能随之变化。确认重置时两个待评估目标均未满足。

**学习者练习：** 实现用例构建和请求目标选择。检查一对原始指令与改变目标指令的视频，区分目标选择错误、操作失败和评分错误。

### C. 评估环境鲁棒性

在独立 LIBERO-plus 环境中评估相机视角和物体布局。正式评估策略前，使用种子 42，为每个主要任务的每个扰动维度无放回选择十个变体。固定名称、元数据、初始状态引用和采样种子。运行时 ID 应从已安装任务套件中解析，不得假设元数据 ID 与运行时索引一致。

每个策略对每个变体执行一个固定回合，共八十个扰动回合。同时在该后端内，为每个主要任务执行二十个无扰动参考回合，共八十个参考回合。通过环境连接层，使用固定的原始任务定义和初始状态构建参考回合。

在完全相同的用例上比较策略。相机对照在条件允许时匹配物理状态，并验证其他场景部分未发生变化。布局用例使用其指定的改变后状态。所有结果明确标注仿真器和后端，不得将所有布局对照都描述为与无扰动状态完全配对的实验。

在每个任务和扰动维度内，对变体用例进行 bootstrap 重采样。将本实验表述为项目抽样研究，不宣称复现完整 LIBERO-plus 基准。

**学习者练习：** 检查扰动，识别变化内容，并解释哪些比较能够支持因果解读。

### D. 准备示范数据并微调策略

比较预训练 SmolVLA、原始指令微调和指令改写微调。示范数据取自固定版本 LIBERO 数据集中选定的四个任务。

使用种子 42，按任务分层，以完整回合为单位划分 70% 训练集、15% 验证集和 15% 留出集。不得将同一示范轨迹中的帧分散到不同集合。保留到原始回合标识的映射。

训练集只构建一次，再制作两份项目自有副本。两组的数值观测、动作、帧数、回合顺序和归一化保持一致。对照组保留标准指令；改写组将回合近似均匀分配给标准指令和四个训练改写模板。每条示范轨迹从头到尾只对应一条一致的指令。

使用 LeRobot 数据工具。修改任务文本的操作会原地编辑数据，因此只修改项目自有副本，绝不修改下载源数据。通过真实数据加载器验证两组仅语言不同。两组训练及其保存的处理流水线均显式保留检查点的归一化统计量。

两组采用相同初始配置：

| 设置 | 选择 |
| --- | --- |
| 初始化 | 相同的预训练 LIBERO 检查点和处理流水线 |
| 微调方式 | LoRA，rank 16，alpha 16 |
| 目标模块 | LeRobot 的 SmolVLA 默认 PEFT 目标模块 |
| 主干网络 | 冻结视觉和语言主干 |
| 批大小 | 4 |
| 精度 | 通过受支持的训练器/Accelerate 接口使用 BF16 |
| 学习率 | `1e-4` |
| 调度 | 预热 500 次更新，随后余弦衰减至 `1e-5` |
| 训练预算 | 每组 10,000 次优化器更新 |
| 检查点间隔 | 每 2,000 次更新 |
| 训练种子 | 两组均为 42 |

先进行一百次更新的冒烟检查，核实可训练参数及损失均为有限数值，保存并重新加载检查点，再执行一个回合。若失败，先诊断并明确调整两组共享配置，再启动任何一组完整训练。两组必须保持相同的样本曝光量和优化预算。

使用开发初始状态，计算标准指令与一个仅用于验证的改写模板上的平均成功率，分别选择两组检查点。并列时选择更早的检查点。最终评估前固定两组选择，绝不根据最终测试结果选模型。

**学习者理解检查：** 解释 LoRA 修改了什么、哪些参数保持冻结、为何需要额外的标准指令训练作为对照，以及为何训练损失下降不能证明指令遵循能力提升。

### E. 衡量并解读结果

学习者先实现基本指标，并使用少量真实回合手工核对：

- 按任务、条件和策略统计成功率。
- 改写差距：改写指令成功率减去原始指令成功率。
- 改变目标后的成功率和首个物体选择结果。
- 配对正确率：在相同初始场景下，原始指令选择 A，改变目标后的指令选择 B。
- 干预增益：改写微调的成功率减去原始指令微调的成功率。

严格的配对选择指标以首个完成的物体目标为准。同时满足多个目标时单独记录，不得任意指定第一个物体。最终请求目标成功率另行报告，以体现先执行了不期望动作的情况。

在智能体指导下，使用 2,000 次重采样计算 95% bootstrap 区间。在每个任务内，以初始状态组为单位重采样，保留该状态下所有改写条件和不同策略的配对结果。汇总时各任务权重相同。结论仅适用于这四个选定任务，以及每个微调组一个训练种子的设置。

同时报告相对于无扰动参考回合的鲁棒性成功率、推理延迟、回合耗时、峰值显存和训练成本。结合改变目标的行为解读空指令表现，任何单一诊断都不能独立证明模型是否使用语言。

人工检查失败时采用简洁分类：选错物体、抓取失败、物体掉落、放置错误、超时和视觉变化引发的失败。无法确定的原因应明确标为未知，基础设施错误单独记录。学习者先写出解读，智能体先质疑混杂因素和替代解释，再协助编辑结论。

### 最终评估预算

| 评估内容 | 每个策略的回合数 |
| --- | ---: |
| 四个任务 × 二十个状态 × 六种语言条件 | 480 |
| 相机/布局变体 | 80 |
| 鲁棒性环境内的无扰动参考回合 | 80 |
| 合计 | 640 |

三个策略共计 1,920 个最终评估回合，不包含开发检查和检查点选择所需运行。排期前根据实测吞吐量估算实际耗时。

| 周次 | 交付物 | 学习者实现或理解检查 |

| 1 | 通过验证的 WSL/CUDA/渲染环境 | 解释观测、机器人状态、末端执行器动作和控制坐标系 |

| 4 | 经过校验的清单和可复现实验执行器 | 构建匹配用例，解释为何只有相同种子还不够 |
| 5 | 改写与改变目标评估器 | 编写指令、请求目标选择和配对比较 |
| 6 | 基线语言结果和不确定性估计 | 实现指标、手工验证并解释局限 |
| 7 | 相机/布局鲁棒性实验面板 | 检查扰动，独立分类若干失败案例 |
| 8 | 数据划分、重标注副本和 LoRA 冒烟检查点 | 检查示范与动作对齐，说明干预依据 |
| 9 | 两组完成的微调运行 | 比较诊断信息，区分损失下降与行为提升 |
| 10 | 已选检查点和完整最终评估 | 执行选择规则，抽查记录结果 |
| 11 | 图表、失败分析和报告草稿 | 先独立解读，包括不支持原假设的证据 |
| 12 | 复现实验和完整作品集 | 独立修改核心代码，并解释完整系统 |

在此周期内不增加仪表盘、其他模型家族或其他仿真器。剩余时间用于加深理解、调试和提高可复现性。

## 5. 验证与完成标准

### 软件验证

使用最少且有实际价值的真实集成检查：

1. 完成渲染、预处理、预测、步进和可播放视频保存，同时校验张量形状和数值有限性。
2. 两次恢复同一仿真器状态，在明确记录的容差内比较状态和观测。
3. 验证两个目标的已知正例和负例状态，包括改变目标实验中完成原始目标后仍继续执行。
4. 通过 LeRobot 加载两份训练数据，验证数值数据相同且语言差异符合预期。
5. 完成训练、保存、重载和一次真实执行。
6. 运行一个小型清单，恢复执行并重新生成一致汇总，确保没有重复回合。

完成实现里程碑前运行代码检查和严格类型检查。不要添加只断言指令措辞或配置文本的测试。

### 独立学习验证

关闭智能体后，学习者必须能够：

- 梳理语言、图像、状态、预处理、预测动作块和仿真动作之间的关系。
- 解释动作执行步数、坐标约定、归一化和策略重置行为。
- 解释各语言对照回答的问题及仍然存在的混杂因素。
- 计算并解读主要指标。
- 根据保存的观测、动作和视频诊断失败。
- 使用行为证据解释微调结果，不仅依赖训练损失。
- 独立修改核心组件并验证其影响。

### 作品集完成标准

交付经过验证的安装与运行说明、锁定依赖、冻结清单、机器可读结果、三个策略的完整比较、带不确定性估计的图表、带注释的成功/失败视频，以及一份涵盖方法、证据、局限和下一步实验的报告。在全新环境中复现一个有代表性的小型实验。

性能提升是假设，不是完成要求。可复现、解释有据的负面结果同样满足研究目标。

留出集仅相对于本项目的微调和调参过程定义，不得宣称其在检查点预训练阶段未被见过。初始范围不包含实体硬件、强化学习、LLM 规划、付费云算力或自动发布。除非明确要求提交，否则所有改动保持未提交状态。
