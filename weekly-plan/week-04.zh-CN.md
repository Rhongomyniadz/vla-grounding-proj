# 第 4 周：实验清单、可靠执行与恢复运行

[English](week-04.en.md) | [简体中文](week-04.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**目标:** 把单次执行扩展为配置明确、能够恢复的实验，同时保留已经建立的控制条件。

**开始条件:** 第 3 周已验证状态恢复，且主实验动作执行步数已明确。

时间预算：五次学习共十二小时主动投入，其中一小时关闭智能体独立完成；电脑运行时间另计。

## 准备与学习

- 阅读实施计划中实验、回合、结果和运行清单的接口约定。
- 理解跨策略共享的场景标识，与包含特定策略及条件的回合标识之间的区别。
- 检查四个主要任务的定义，以及固定版本基准如何解析任务名称、物体和 ID。

## 分次任务

### 1. 固定任务与初始状态标识 (2 小时)

- [ ] 你：按完整名称解析四个主要任务，核实原始物体、替代物体和篮子目标区域。
- [ ] 每个任务预留五个开发状态及二十个不同的最终状态，保存明确引用和哈希。
- [ ] 你：明确配对采样种子，使同一状态在不同指令和策略下使用相同策略随机数种子。

### 2. 构建首个清单及校验 (3 小时)

- [ ] 你：使用固定任务/状态列表，为标准指令开发用例实现首个用例构建函数。
- [ ] 智能体：实现结构化配置校验、稳定回合标识、解析后资源元数据和明确命令输入。
- [ ] 分配仿真资源前，验证必填字段、错误状态引用、不兼容特征映射和重复用例标识。

### 3. 执行并恢复小型真实实验 (3 小时)

- [ ] 每个主要任务运行两个开发状态，得到八个记录完整的标准指令回合。
- [ ] 在回合完成之间中断开发运行，再按同一清单恢复，验证每个用例恰好出现一次。
- [ ] 分别检查较短的开发超时和真实配置错误，区分失败回合与未完成运行。

### 4. 独立审查用例构建后再复核 (2 小时)

- [ ] 前一小时关闭智能体，将一条清单记录沿任务解析、状态恢复、策略种子、输出标识和汇总纳入规则逐步追踪。
- [ ] 利用真实记录验证：指令/策略标识可变化，而匹配初始状态和采样种子应保持不变。
- [ ] 后一小时与智能体审查你的检查及构建函数，修正隐藏设置或重复标识问题。

### 5. 固定执行器约定并交接 (2 小时)

- [ ] 确认更改配置必须生成新的清单/运行标识，不能悄悄改变已有恢复实验。
- [ ] 保存八用例开发实验、清单、轨迹引用、视频和完成覆盖汇总。
- [ ] 准备第 5 周语言用例要求，不运行最终留出实验。

## 证据与完成检查

- [ ] 四个任务及互不重叠的开发/最终状态引用明确且可找回。
- [ ] 八个真实开发用例可以中断并恢复，不丢失或重复已完成记录。
- [ ] 错误保留可操作的上下文，超时仍算有效失败，最终评估状态没有用于调参。

## 关闭智能体后解释

1. 配对比较需要共享哪些标识，哪些标识必须区分不同运行？
2. 为什么不能悄悄把异常算成普通操作失败？
3. 恢复运行前如果渲染、预处理或策略设置改变，应如何处理？

## 给编程智能体的建议请求

> 围绕我的用例构建函数，实现清单校验、产物处理和恢复支持，并用真实八用例开发实验验证。

## 进入下一周的条件

执行过程明确且可以恢复，学习者能够将清单用例追踪到结果记录后，再继续。
