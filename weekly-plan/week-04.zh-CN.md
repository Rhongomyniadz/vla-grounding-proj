# 第 4 周：实验清单、可靠执行与恢复运行

[English](week-04.en.md) | [简体中文](week-04.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 把单次执行扩展为配置明确、能够恢复的实验，同时保留已经建立的控制条件。

**开始开发:** 已明确第 3 周状态/重置约定；重置检查待完成时可先编写模型、用例构建和执行器代码。

**运行电脑前置条件:** 第 3 周已验证状态恢复，且主实验动作执行步数已明确。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

1. **在编码电脑准备：** 编写用例构建、结构化清单校验、稳定标识、源码快照来源、相对运行目录产物引用和恢复逻辑。
2. **在运行电脑执行：** 第 3 周目标门槛通过后，解析固定任务/状态目录，执行八用例中断/恢复、超时及真实错误检查。
3. **带回审查：** 带回任务/状态哈希、解析清单、源码/锁文件/配置标识、八用例结果及产物、错误日志和恢复前后覆盖。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

理解目标：

- 区分物理场景标识、配对采样种子、策略/条件回合标识及整次运行规格标识。
- 从一行清单追踪状态、指令、结果和视频，并用八用例面板说明覆盖。
- 解释部分写入/异常为何未完成、超时为何是结果、变化设置为何不能沿用原标识恢复。

- 检查四个主要任务的定义，以及固定版本基准如何解析任务名称、物体和 ID。

- 从[任务与评估方案](../doc/IMPLEMENTATION_PLAN.zh-CN.md#3-实验方案)找到四个完整任务名及开发/最终划分要求。
- 结合固定版本环境重置路径与现有回合循环，识别显式用例应覆盖自动推进状态索引的位置。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **任务/状态目录。** 实现目录构建，按方案完整任务名解析固定基准，验证原始/替代物体和目标区域，记录真实运行 ID。解析并哈希明确初始状态，按权威方案预留互不重叠的开发/最终组。
2. **清单模型与用例构建。** 实现经过校验的实验、回合、结果和运行清单记录，要求全部重建字段。用纯函数根据明确任务/状态/策略/种子输入构建标准开发用例，创建仿真前拒绝缺引用、重复用例及不兼容映射。
3. **稳定标识与来源。** 按物理场景/控制输入生成场景标识，再结合策略/条件生成回合标识。在解析运行清单保存源码快照、锁/配置及模型/数据/资源标识。可迁移引用与本地路径分开，产物使用相对运行目录链接。
4. **清单执行。** 增加清单驱动命令，调用已验证单回合循环，通过 `tqdm` 显示结构化进度，为每个预期用例写入一个强类型结果和产物集合。超时算已完成但不成功的回合，基础设施执行无效时保留上下文并报错停止。
5. **正确恢复与覆盖。** 仅在有意义规格不变时恢复未完成回合，区分不完整/部分产物与有效完成记录，拒绝冲突运行标识并防止重复结果。按回合 ID 计算计划、完成、失败及未完成覆盖，不依赖目录顺序。
6. **真实面板与文档。** 执行计划中的小型标准面板，在已完成回合间中断并恢复，验证每用例一次的覆盖、真实超时/错误及变化规格拒绝。在代码指南说明模型关系、ID 生成、完成判断、路径解析和一行清单到视频的实例。

## 分次任务

### 1. 固定任务与初始状态标识 (2 小时)

**位置：** 编码电脑：设计目录和配对字段。运行电脑：冻结前解析真实任务 ID、物体/区域定义及状态哈希。

**详细操作步骤**

1. 按完整名称解析主要任务并检查定义，将运行 ID 作为元数据记录，不作为唯一长期标识。

2. 列出可用初始状态，按计划选择互不重叠的开发和最终组，生成用例前核对数量与指纹。

3. 逐场景确认原物体、替代物体和篮子区域确实存在，不从自然语言标题推断。

4. 写出含任务名、状态引用、指令标识、策略标识和采样种子的概念用例表，标记配对比较必须共享的列。

**应得到的结果:** 经过审查的任务/状态目录，以及场景标识与运行标识的明确区别。

**如果没有达到预期:** 运行任务顺序不同于预期时，按已安装套件解析名称，不再硬编码另一个索引。

**本次完成清单**

- [ ] 按完整名称解析四个主要任务，核实原始物体、替代物体和篮子目标区域。
- [ ] 每个任务预留五个开发状态及二十个不同的最终状态，保存明确引用和哈希。
- [ ] 明确配对采样种子，使同一状态在不同指令和策略下使用相同策略随机数种子。

### 2. 构建首个清单及校验 (3 小时)

**位置：** 编码电脑：实现用例构建及校验。真实目录可用后在目标检查引用解析。

**详细操作步骤**

1. 编写用例构建函数，先对每个选定开发状态生成一个标准用例，输入明确且不可变。

2. 按架构必需记录序列化并校验，要求所有重建所需标识及设置，仅忽略外部无关字段。

3. 场景标识围绕物理任务/状态和配对控制信息；独立回合标识包含策略和条件，防止不同输出相互覆盖。

4. 创建仿真器前检查错误及重复输入，验证缺字段、状态不存在和映射不兼容会给出可操作错误。

**应得到的结果:** 标识可复现、不会悄悄指向其他场景或策略的清单。

**如果没有达到预期:** 不能通过接受空任务、替换默认状态或丢弃未知条件来处理无效清单。

**本次完成清单**

- [ ] 使用固定任务/状态列表，为标准指令开发用例实现首个用例构建函数。
- [ ] 实现结构化配置校验、稳定回合标识、解析后资源元数据和明确命令输入。
- [ ] 分配仿真资源前，验证必填字段、错误状态引用、不兼容特征映射和重复用例标识。

### 3. 执行并恢复小型真实实验 (3 小时)

**位置：** 运行电脑：执行、中断并恢复八用例面板，区分超时和基础设施错误。

**详细操作步骤**

1. 生成计划中的八用例标准开发面板，输出解析结果，运行前逐项检查任务与状态关联。

2. 执行部分用例，在已完成回合之间中断，不改清单直接恢复，比较前后完成 ID。

3. 确认产物写入能区分完整回合与部分文件，部分记录不能导致恢复时跳过未完成用例。

4. 用独立标签的短上限开发运行检查超时，用真实无效配置检查错误；只有前者算已完成失败回合。

**应得到的结果:** 每个预期用例恰有一条结果的八用例面板，以及恢复正确性的证据。

**如果没有达到预期:** 结果重复或缺失时，先修复回合标识及完成记账，再运行更多用例。

**本次完成清单**

- [ ] 每个主要任务运行两个开发状态，得到八个记录完整的标准指令回合。
- [ ] 在回合完成之间中断开发运行，再按同一清单恢复，验证每个用例恰好出现一次。
- [ ] 分别检查较短的开发超时和真实配置错误，区分失败回合与未完成运行。

### 4. 审查用例构建并记录结论 (2 小时)

**位置：** 编码电脑：审查返回清单/结果链路，手工统计覆盖。

**详细操作步骤**

1. 选一条清单，找到其任务定义、序列化初始状态、实际指令、策略种子和输出记录。

2. 解释为何它与另一策略/条件用例的 ID 不同，但物理状态配对标识相同。

3. 用真实记录手算覆盖表，区分计划、完成、任务失败及未完成用例。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 从一条清单到结果和覆盖汇总的手工验证链路。

**如果没有达到预期:** 如果只能按目录顺序找到视频，应补足用例到产物引用。

**本次完成清单**

- [ ] 将一条清单记录沿任务解析、状态恢复、策略种子、输出标识和汇总纳入规则逐步追踪。
- [ ] 利用真实记录验证：指令/策略标识可变化，而匹配初始状态和采样种子应保持不变。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 固定执行器约定并交接 (2 小时)

**位置：** 编码电脑：固定约定并检查覆盖。运行电脑：恢复前验证修改规格会被拒绝。

**详细操作步骤**

1. 在开发检查中更改一个关键设置后尝试恢复，要求明确配置标识错误或使用显式新运行标识。

2. 将已验证清单、解析后环境/模型元数据同八用例结果一起保存。

3. 执行器约定写进代码，概念推理保留对应的 `doc/` 双语文档；实际约定变化时才同步更新架构双语文档。

4. 为下周明确指令/目标用例准备扩展位置，不提前实现猜想中的多种任务模式。

**应得到的结果:** 能恢复同一实验，并区分不同实验的执行器。

**如果没有达到预期:** 不能让当前环境变量悄悄重定义已有清单条件。

**本次完成清单**

- [ ] 确认更改配置必须生成新的清单/运行标识，不能悄悄改变已有恢复实验。
- [ ] 保存八用例开发实验、清单、轨迹引用、视频和完成覆盖汇总。
- [ ] 准备第 5 周语言用例要求，不运行最终留出实验。
