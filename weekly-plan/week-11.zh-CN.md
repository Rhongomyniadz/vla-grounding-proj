# 第 11 周：分析结果并记录解读

[English](week-11.en.md) | [简体中文](week-11.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 分析并说明证据、不确定性和失败模式，交付完整双语报告。

**开始开发:** 已约定报告结构和分析约定；最终数值、图表及解读依赖第 10 周已审查的返回证据。

**运行电脑前置条件:** 第 10 周已提供冻结且审查过的最终结果，覆盖完整或已明确说明局限。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

1. **在编码电脑准备：** 准备报告提纲和分析入口；真实最终记录返回后，撰写有证据的解读，并用已声明依赖在本地生成/核对图表。
2. **在运行电脑执行：** 使用冻结目标结果集，取回审查需要的引用产物；只有解决真实证据/正确性缺口时才需新执行。
3. **带回审查：** 带回全部最终清单/结果/覆盖记录、计算日志及十二个选定真实回合证据包，包含哈希和相对运行目录链接；报告保留目标来源。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

## 阅读内容与理解目标

按以下顺序阅读。尚不存在的源码会明确标注；完成本里程碑前，将计划代码描述替换为实际文件/符号链接，并补充对应证据引用。

| 顺序 | 必读内容 |
| --- | --- |
| 1. 文档 | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md#e-衡量并解读结果)：指标、区间、失败分类及推断局限。[代码指南](../doc/CODE_GUIDE.zh-CN.md)：已交付分析及产物路径结构。 |
| 2. 当前代码 | [evidence.py](../src/vla_grounding/evidence.py)，以及此前实际交付的结果读取、分组指标/bootstrap、绘图/导出和覆盖模块。 |
| 3. 沿调用阅读 | 报告/图表生成、示例回合选择/注释函数仍待实现；完成后阅读真实输入及转换。 |
| 4. 本里程碑代码/证据 | 在 `doc/` 创建双语结果报告后，阅读报告、冻结清单/覆盖引用及十二个采样回合包；文件存在前不视为已实现。 |

理解目标：

- 将一个主要数值及一个策略差值追踪到配对记录、分母、区间及图注。
- 区分实测发现、因果假设和未知，解释措辞鲁棒性与改变目标响应的区别。
- 说明负面证据、示例采样局限、单种子/四任务不确定性，以及哪些新实验会改变主张。

## 准备与学习

- 回顾早期预测、固定指标定义，以及最终目标成功与首个物体选择的区别。
- 复核 bootstrap 分组及四任务、每组一个训练种子、基准重叠和抽样鲁棒性面板的局限。
- 检查结果结构及产物引用，确保报告中的每项主张都能指向实测证据。

## 阅读路线与理解目标

- 决定图表叙事前，重读[分析解读约定](../doc/IMPLEMENTATION_PLAN.zh-CN.md#e-衡量并解读结果)及固定指标实现。
- 阅读对应的 `doc/` 双语文档早期假设，包括错误预测，区分事前验证与事后解释。
- 检查一条从清单、真实结果、轨迹、视频到分组统计和图表的完整链路，报告主要主张均需可找回的证据链。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **冻结结果读取。** 实现或完善可迁移结果/产物读取器，校验最终运行标识及覆盖，不导入仿真器。保留目标来源不变，从明确本地运行根目录解析复制产物，在所有汇总保留已知不完整状态。
2. **最终定量分析。** 复用已验证指标/不确定性函数，重新生成任务/条件/策略表、配对差值、首物体汇总、鲁棒性/参考比较及实测计算成本。开发/选择结果单独标记，用真实配对记录核对代表性主要数值。
3. **图表及表格输出。** 实现可复现绘图/导出入口，接收冻结记录及明确输出路径，标明轴/单位、样本数、后端、覆盖和区间定义。保存输出到输入的可追溯引用，使每个报告数值可重建。
4. **示例回合选择与注释。** 为计划回合审查面板实现有记录的选择过程。对每个例子对齐准确指令、状态/动作/谓词轨迹及视频帧，仅注释证据支持的失败分类并保留未知原因，不用示例采样估计类别比例。
5. **有据双语报告。** 撰写研究问题、引用方法、结果、不确定性、示例、替代解释、局限及下一实验。每项主要主张关联实测比较和反面证据，区分假设与发现，不仅凭训练损失推断提升。
6. **一致性与结构说明。** 对冻结记录核对图表/表格/图注，同步双语报告数字及限定语。代码指南更新读取/汇总/绘图/注释结构、产物路径流和证据链接。事后想法明确留作未来工作，不重新调优原最终研究。

## 分次任务

### 1. 先解释结果再润色 (2 小时)

**位置：** 编码电脑：根据已审查的返回最终表格和真实用例，撰写有证据的书面解读。

**详细操作步骤**

1. 撰写研究问题及有证据的解读，包含不确定性和竞争解释。

2. 先比较基线与标准对照以理解额外微调，再比较改写与标准对照以分析目标语言干预。

3. 分别讨论原措辞、留出改写、改变目标、空指令及鲁棒性，再形成总体结论。

4. 对每项主张列明测量量、不确定性、支持案例、反对案例和替代解释。

**应得到的结果:** 不依赖积极结果的证据提纲。

**如果没有达到预期:** 没有可靠提升时解释观察到的局限，不看答案后更换问题。

**本次完成清单**

- [ ] 检查汇总表，先写出对标准、改写、改变目标、空指令和鲁棒性结果的解释。
- [ ] 识别支持及反对干预假设的证据，包括可能出现的操作能力退化。
- [ ] 区分测量发现、因果假设和未知因素，不编造积极叙事。

### 2. 生成并核对最终图表 (3 小时)

**位置：** 编码电脑：用已声明分析依赖从复制的冻结记录重建最终图表，手工核对一个主要数值。

**详细操作步骤**

1. 用已验证分析函数，直接从冻结结果集重新生成全部图表。

2. 核对任务级及整体率、配对差、首个物体选择、扰动/参考对照、样本量和资源成本。

3. 手工把一个关键值和一个改写/对照差值核对到底层配对记录。

4. 检查坐标、单位、标签、后端及区间定义，不无标签地把开发图混入最终图。

**应得到的结果:** 数值和标签都能独立重建的最终图表。

**如果没有达到预期:** 数量或配对成员不符时，图再有说服力也不代表统计有效。

**本次完成清单**

- [ ] 生成分任务/条件成功率、配对目标选择、鲁棒性对照、不确定性区间和计算成本表。
- [ ] 至少手工将一个关键图表数值及一个策略差值追溯到原始配对记录。
- [ ] 验证标签披露样本量、后端、开发/最终状态，以及区间的条件性解释。

### 3. 按明确抽样规则检查失败 (3 小时)

**位置：** 编码电脑：按声明规则选择并检查十二个真实返回回合证据包；从目标取回缺失引用产物。

**详细操作步骤**

1. 明确计划展示回合的选择方法，涵盖策略、条件及实际存在结果。

2. 逐例对齐指令、首个相关观测、预测/执行动作、目标谓词和视频帧。

3. 只有轨迹支持时才给失败分类，未知或多种可能原因应保留。

4. 注释中标明用例标识和展示内容，不用少量案例估计失败类别占比。

**应得到的结果:** 可追踪、只说明机制而不替代全量统计的注释案例。

**如果没有达到预期:** 视频似乎成功而谓词失败时，先检查时间和目标语义，再归因模型。

**本次完成清单**

- [ ] 按记录在案的规则选择十二个真实回合，每策略四个，覆盖实际存在的条件和结果。
- [ ] 结合状态、动作和谓词轨迹检查视频，按约定分类失败，无法确定时标为未知。
- [ ] 用案例说明机制，不用这些少量案例估计总体失败频率，也不取代完整量化结果。

### 4. 论证并记录一项研究结论 (2 小时)

**位置：** 编码电脑：使用返回统计、区间和轨迹独立论证一个结论。

**详细操作步骤**

1. 选择报告准备使用的一项结论。

2. 用整体对照、区间和一条轨迹支持，解释为何个案本身不足。

3. 写出最强替代解释及能区分它的具体未来实验。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 证据充分、且明确未知部分的结论。

**如果没有达到预期:** 不能用仅重采样本次状态的区间推断新种子或新任务行为。

**本次完成清单**

- [ ] 用一个表格、一个区间和一个视频/轨迹示例支持某项主张。
- [ ] 写出最强替代解释，并说明哪项新增实验能够区分它。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 完成报告并核对双语一致性 (2 小时)

**位置：** 编码电脑：完成并同步双语报告，使用可迁移产物链接和真实目标来源。

**详细操作步骤**

1. 报告按研究问题、引用方法、实测结果、失败机制、局限和下一实验组织。

2. 精确设置引用清单及架构文档，不另维护一张独立参数表。

3. 翻译并编辑撰写的有证据报告，逐语言核对数字、限定语、范围和负面发现。

4. 事后探索明确标为未来工作，验证实现确实改设计时同步相关架构文档。

**应得到的结果:** 主张一致、产物可找回、有证据的双语报告。

**如果没有达到预期:** 译文不能把暂定机制或条件性结果强化为普遍结论。

**本次完成清单**

- [ ] 撰写包含问题、方法引用、结果、不确定性、失败示例、局限和下一步实验的报告。
- [ ] 根据有证据的解读，完成中英文报告一致性、图注、产物链接和编辑。
- [ ] 若验证后的系统与计划不同，同步更新架构/实施文档双语版本；不把根据测试调参算作原有留出研究的一部分。

## 证据与完成检查

- [ ] 文档已就绪：双语设计/代码指南覆盖全部已实现结构、理由、接口及验证状态。
- [ ] 开发已就绪：本周源码/配置及适用本地检查已包含在明确标识的交接中。
- [ ] 目标已验证：所需真实目标证据已返回，并按该交接完成审查。
- [ ] 每项关键主张均可追溯到实测结果，并包含不确定性及负面证据。
- [ ] 案例采用明确选择规则，保留未知原因，不代替完整面板指标。
- [ ] 报告能为解读提供依据，报告及所有更新的架构文档在两种语言间保持一致。

## 可选复核问题

1. 什么证据能区分措辞鲁棒性与改变目标后的响应能力？
2. 若改写微调改善一个条件却损害标准成功率，报告应如何描述权衡？
3. 哪些局限需要更多任务或训练种子，而不是反复运行同一用例？
