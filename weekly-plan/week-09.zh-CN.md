# 第 9 周：运行两组受控微调

[English](week-09.en.md) | [简体中文](week-09.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 完成可比较的标准指令与改写指令训练，并理解训练诊断及其局限。

**开始开发:** 已明确两组训练约定；第 8 周完成前可准备启动/恢复审查，但不能开始完整训练。

**运行电脑前置条件:** 第 8 周已验证数据等价性、共享配置、可训练参数、检查点重载，以及实测耗时和显存要求。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

1. **在编码电脑准备：** 比较两组配置并实现明确启动/恢复步骤和日志审查；仅在目标冒烟证据存在后安排运行。
2. **在运行电脑执行：** 第 8 周目标门槛通过后，从同一基础执行两组，检查初始更新，保留检查点并验证新进程重载执行。
3. **带回审查：** 带回解析调用/配置哈希、数据/处理器标识、真实更新/损失/资源日志、恢复来源、检查点目录及重载视频。大权重/优化器状态保留在目标。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

理解目标：

- 识别两组允许差异，说明同一预训练基础及相同样本/更新预算。
- 解释损失、学习率、梯度、可训练权重和资源诊断，不把更低损失等同语言落地提升。
- 解释受支持恢复状态，以及中断或不等量训练如何影响选择前可比性。

## 准备与学习

- 重新检查实施计划中的共享配置及冻结训练清单，不另建重复且可能冲突的参数说明。
- 检查固定版本 SmolVLA 的训练目标，识别预测值、监督目标、损失归约方式和冻结/可训练模块。
- 理解数据顺序、优化器更新、归一化、样本曝光量及初始化如何混淆微调比较。

## 阅读路线与理解目标

- 把共享[训练配置](../doc/IMPLEMENTATION_PLAN.zh-CN.md#d-准备示范数据并微调策略)与已验证冒烟配置并排阅读。
- 检查[固定版本训练循环](https://github.com/huggingface/lerobot/blob/v0.6.1/src/lerobot/scripts/lerobot_train.py)中的优化更新、学习率调度、检查点保存和恢复。
- 沿已安装策略真实损失计算，从处理后动作监督到归约，解释损失测量什么，再解读曲线。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **可比启动规格。** 根据相同已验证基础、数据划分、归一化及共享配置生成完整解析的标准/改写运行配置。逐字段验证允许的语言/输出差异，拒绝意外从冒烟权重或另一已训练组初始化。
2. **明确启动命令。** 为两组分别提供可复现调用，明确配置/数据/基础/输出路径及不可变标识。启动前检查实测磁盘/检查点/耗时需求，随运行保存准确命令、源码/配置/锁哈希和包/硬件信息。
3. **训练进度与诊断。** 接入上游训练输出，结构化本地记录优化器更新、样本暴露、损失、学习率、可训练模块诊断及资源使用。无人值守继续前检查真实早期批次和更新，保留警告及真实失败。
4. **检查点目录与受支持恢复。** 为每次必需保存记录优化器步、权重、处理器和训练状态标识。仅在规格兼容且不变时经固定训练器支持接口恢复，保留中断及恢复来源，不从目录名推断完成或隐藏预算不等。
5. **两组比较与重载审查。** 核对初始化、数值数据、归一化、样本暴露及完成更新数，仅用开发证据排查差异。模型选择前在新进程重载每组一个已保存检查点，并保存开发执行。
6. **完成记录与说明。** 生成可审查候选检查点清单及两组最终进度/覆盖记录。说明启动/恢复结构、优化器/检查点关系、允许差异、实测成本和损失解读局限；真实证据齐全前完整训练及验证选择前置条件保持待完成。

## 分次任务

### 1. 审查两组运行规格 (2 小时)

**位置：** 编码电脑：比较配置并准备启动命令。运行电脑：确认真实存储、检查点占用及实测预算。

**详细操作步骤**

1. 比较完整解析配置、源/派生数据标识、处理器、归一化、可训练参数、优化设置、种子和更新次数。

2. 列出允许差异，仅含预期指令来源和输出/运行标识，其他差异必须在启动前排查。

3. 确认两组从相同预训练基础初始化，而不是冒烟检查点或另一组已训练权重。

4. 按实测占用检查存储和保留策略，用剩余更新乘实测单更新耗时估计运行，启动/评估另算。

**应得到的结果:** 审查过的成对运行规格，以及实测资源和排期估算。

**如果没有达到预期:** 配置差异应修正来源，不只修改打印日志。

**本次完成清单**

- [ ] 逐字段比较完整训练配置，只允许预期的指令来源和输出标识差异。
- [ ] 确认两组从同一预训练检查点开始，使用相同源回合和共享训练种子，且发布/外部追踪保持关闭。
- [ ] 准备明确启动及受支持恢复命令、本地检查点位置和结构化进度/资源日志。

### 2. 启动并检查标准指令对照组 (3 小时)

**位置：** 运行电脑：启动并检查标准指令对照组，随后让已验证长任务无人值守运行。

**详细操作步骤**

1. 用已验证命令/配置启动标准组，保留精确解析调用。

2. 首个区间检查数据标签、优化进度、学习率、目标梯度、显存和有限损失。

3. 首次周期保存后核对元数据，确认模型、处理器和训练状态对应同一次更新。

4. 检查通过再允许长时间无人值守运行，保留警告和真实完成状态。

**应得到的结果:** 配置、进度和保存状态一致的标准训练运行。

**如果没有达到预期:** 损失下降不证明语言条件有效，标签可疑时检查真实处理后批次。

**本次完成清单**

- [ ] 核实实测预算和输出路径后启动标准指令组，长时间电脑运行不计入本次主动投入时长。
- [ ] 检查初期损失、有限梯度、可训练模块、学习率变化、显存和实际更新次数。
- [ ] 保留周期检查点及源模型/处理流水线标识，不仅凭训练曲线判断指令遵循是否提升。

### 3. 启动并检查改写微调组 (3 小时)

**位置：** 运行电脑：以相同优化/样本预算，启动并检查独立改写组。

**详细操作步骤**

1. 独立从同一预训练基础、同一共享配置启动改写组。

2. 检查真实批次文本只含标准和训练改写，数值监督不变。

3. 比较累计优化更新和样本曝光，不用墙钟时间代替训练量相等。

4. 保留周期检查点和日志；资源/数值问题迫使改配置时记录并恢复两组可比性。

**应得到的结果:** 标签已验证、优化预算相等的真正可比干预组。

**如果没有达到预期:** 改写组不能继承对照组优化器状态或已训练参数。

**本次完成清单**

- [ ] 独立从同一预训练模型启动改写组，绝不能从已训练的标准指令对照组继续训练。
- [ ] 验证真实批次只使用分配的标准/训练改写标签，没有验证或最终测试措辞。
- [ ] 核对优化及样本预算一致，并按计划间隔保留检查点；必须更改配置时，不继续不公平比较。

### 4. 审查训练证据并记录结论 (2 小时)

**位置：** 编码电脑：比较相同真实更新区间的返回日志；运行异常在目标调查。

**详细操作步骤**

1. 选择两组相同更新区间。

2. 比较真实更新数、学习率、损失、梯度/资源诊断和输入标识，解释哪些差异可能来自文本。

3. 列举至少两个损失不同但不代表目标选择更好的解释，例如采样波动或监督难度差异。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 结论范围恰当的独立训练诊断比较。

**如果没有达到预期:** 不凭损失曲线选择喜欢的检查点，下周按验证规则选择。

**本次完成清单**

- [ ] 用实际损失、学习率、更新次数和样本元数据比较两组某个检查点区间。
- [ ] 解释至少两个训练差异未必转化为闭环行为提升的原因。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 验证完整且可重载的训练产物 (2 小时)

**位置：** 运行电脑：验证更新完成及检查点重载/回合。编码电脑：审查返回目录并准备选择。

**详细操作步骤**

1. 确认两组达到声明优化预算，每个计划检查点存在且步骤标识准确。

2. 在新进程分别加载两组检查点，使用保存预处理和相同基础版本运行开发回合。

3. 若发生中断，保留恢复来源，验证更新记账及数据曝光仍可比。

4. 准备开发验证面板并列出候选检查点，选择结束前不获取最终测试结果。

**应得到的结果:** 两组完整且能重载的训练，已可按预先规则验证选择。

**如果没有达到预期:** 目录名叫 final 或 last 不代表达到预算，应核对记录更新状态。

**本次完成清单**

- [ ] 确认两组均达到计划中的 10,000 次更新，并保留五个周期检查点、配置、优化器状态和处理流水线。
- [ ] 分别重载两组的已保存检查点并运行开发回合，记录真实加载或执行失败。
- [ ] 准备第 10 周固定的开发验证用例，在选择冻结前不获取最终评估结果。

## 可选复核问题
