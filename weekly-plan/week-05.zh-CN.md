# 第 5 周：语言用例与正确的目标评分

[English](week-05.en.md) | [简体中文](week-05.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**目标:** 实现受控指令比较，并验证改变目标时确实评估了被请求的物体。

**开始条件:** 第 4 周已固定任务/状态标识，具备用例构建函数和可恢复的开发实验执行。

时间预算：五次学习共十二小时主动投入，其中一小时关闭智能体独立完成；电脑运行时间另计。

## 准备与学习

- 阅读实施计划中的语言实验方案，检查 LIBERO 现有目标谓词及终止路径。
- 理解改写不变性、改变目标后的响应和空指令行为分别检验什么性质。
- 检查四个场景中的真实物体与篮子区域标识，不能只凭任务名称定义评分器。

## 分次任务

### 1. 先设计指令再实现 (2 小时)

- [ ] 你：编写标准、改写、改变目标和空指令开发示例，并预测预期行为。
- [ ] 编写四个训练改写模板、一个仅用于验证的模板和三个最终测试模板，保持目标及目的位置明确。
- [ ] 微调前固定模板家族并标记用途，检查语义等价性和分词结果，但不运行最终测试回合。

### 2. 实现语言用例构建 (3 小时)

- [ ] 你：扩展自己的构建函数，附加指令标识、原始文本、请求物体、目标谓词，以及匹配状态和种子引用。
- [ ] 从同一场景构建标准与改变目标用例，不通过加载另一个任务更换请求物体。
- [ ] 智能体：审查序列化和分词检查，确保环境原有任务说明不会覆盖实验指令。

### 3. 用真实状态验证谓词和终止逻辑 (3 小时)

- [ ] 你：使用 LIBERO 现有谓词实现请求目标选择，评估识别首次完成所需的相关物体入篮目标。
- [ ] 确认重置时两个目标均为假，利用已知正例仿真状态验证放入 A 或 B 仅满足对应谓词。
- [ ] 智能体：审查环境边界，确保完成旧目标不会结束改变目标回合，并明确记录同时首次完成的多个目标。

### 4. 独立检查配对失败后再复核 (2 小时)

- [ ] 前一小时关闭智能体，结合状态、文本、动作、谓词和视频检查一对原始/改变目标开发回合。
- [ ] 用具体证据将结果归为目标选择错误、操作失败或评分/执行错误。
- [ ] 后一小时与智能体质疑该判断，必要时进行一次受控后续检查。

### 5. 运行并审查开发条件矩阵 (2 小时)

- [ ] 只在开发状态上运行标准、训练改写、改变目标和空指令条件。
- [ ] 检查配对初始状态哈希与策略采样种子一致，指令及请求目标字段按设计变化。
- [ ] 保存实际指令和分词检查，最终测试模板与最终初始状态不参与开发执行。

## 证据与完成检查

- [ ] 自己编写的用例构建和目标选择逻辑能够生成有效的同场景语言对照。
- [ ] 真实状态检查验证两个请求目标谓词，以及改变目标时的终止行为。
- [ ] 训练、验证和最终模板集合明确、互不重叠，没有被悄悄替换。

## 关闭智能体后解释

1. 为什么改写表现很好仍可能意味着指令遵循能力较弱？
2. 如果改变目标回合仍使用原任务成功谓词评分，会得出什么错误结论？
3. 最终完成请求与首先选择正确物体有何区别？

## 给编程智能体的建议请求

> 审查我的语言用例构建和谓词选择，验证真实状态评分及旧目标终止处理，并让我先解释实验结果。

## 进入下一周的条件

只有文本改变确实更新请求目标评分器且不改变物理场景，并通过真实状态检查后，才进入下一周。
