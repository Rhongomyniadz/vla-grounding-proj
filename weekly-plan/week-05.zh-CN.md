# 第 5 周：语言用例与正确的目标评分

[English](week-05.en.md) | [简体中文](week-05.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 实现受控指令比较，并验证改变目标时确实评估了被请求的物体。

**开始开发:** 已有第 4 周清单/用例接口和语言方案；运行评分验证是单独门槛。

**运行电脑前置条件:** 第 4 周已固定任务/状态标识，具备用例构建函数和可恢复的开发实验执行。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

1. **在编码电脑准备：** 编写模板家族、语言用例构建和目标选择器，审查固定谓词/终止源码，暂不宣称可用。
2. **在运行电脑执行：** 第 4 周目标门槛通过后，验证真实物体/区域名、分词、真实正负谓词状态、原目标终止及开发语言配对。
3. **带回审查：** 带回准确文本/词元、匹配状态/种子记录、谓词真值表、首目标/终止原因轨迹、开发结果及配对视频。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

理解目标：

- 解释改写、改变目标及空指令分别回答什么问题及其混杂因素。
- 追踪实际文本到词元，说明同场景配对哪些共享、哪些改变。
- 结合真实真值表/轨迹说明旧目标终止、初始谓词为假、首物体并列及最终成功。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **指令注册表与划分校验。** 实现结构化注册表，覆盖标准、训练、仅验证、最终留出、改变目标及空条件。明确物体/操作/目的位置及模板标识，校验语义一致和划分互斥；微调前冻结措辞，不按执行成功率选择最终模板。
2. **语言用例构建。** 扩展纯函数用例构建，返回准确文本、条件/模板标识、请求物体/目标及继承状态/种子引用。原始/改变目标配对固定物理场景，仅允许预期语言/目标/回合标识不同，执行前验证配对。
3. **策略文本与分词检查。** 将用例文本沿真实观测及检查点处理路径传递，保留有意空内容，检查词元/掩码，拒绝丢失必需物体/目的位置措辞。防止后续环境任务说明覆盖输入指令。
4. **请求目标评分。** 根据已核实原生物体/区域谓词参数实现目标选择。每个实际步骤评估所有相关物体放置谓词，保留首个满足集合及同时并列，分别报告最终请求目标成功；要求重置时两个竞争目标均为假。
5. **终止集成。** 将旧基准目标终止事件与真实仿真故障、超时分开。改变目标回合在原目标完成后继续，直到请求目标或其他有效停止条件。保留结束原因及谓词轨迹，不盲目丢弃全部终止信号。
6. **真实开发验证及说明。** 用已知负/正真实状态验证两个评分器，证明原目标完成后继续执行。仅运行允许的开发条件，核对文本/状态/种子匹配及配对视频。在代码指南说明指令来源、用例差异、谓词真值表、并列语义和终止流程。

## 分次任务

### 1. 先设计指令再实现 (2 小时)

**位置：** 编码电脑：设计并隔离指令家族。运行电脑：冻结前验证真实场景标识和检查点分词。

**详细操作步骤**

1. 改写前先把原意拆成物体、操作和目的位置，例如字母汤开发指令仍必须请求把字母汤放入篮子。

2. 构建一条等价开发改写和一条改变目标指令，逐词比较并指出预期语义差异。

3. 建立计划中的训练、验证和最终模板家族，不只分离完全相同字符串，也避免各划分充满同一模板的微小变体。

4. 逐条核对填充指令、场景物体标识和分词输出，固定最终模板后不通过执行来筛选措辞。

**应得到的结果:** 能够说明语义用途和划分依据的指令注册表。

**如果没有达到预期:** 若改写引入歧义代词、遗漏物体、改变目的位置或增加动作，应在冻结前修正。

**本次完成清单**

- [ ] 编写标准、改写、改变目标和空指令开发示例，并预测预期行为。
- [ ] 编写四个训练改写模板、一个仅用于验证的模板和三个最终测试模板，保持目标及目的位置明确。
- [ ] 微调前固定模板家族并标记用途，检查语义等价性和分词结果，但不运行最终测试回合。

### 2. 实现语言用例构建 (3 小时)

**位置：** 编码电脑：实现同场景语言用例。运行电脑：追踪真实处理器输入、掩码及请求目标映射。

**详细操作步骤**

1. 扩展构建函数，显式返回指令文本、请求物体/目标和继承的物理状态标识。

2. 逐字段比较同状态原始/改变目标对照，只允许预期语言/目标元数据和回合标识变化。

3. 沿传给分词器的真实批次追踪文本，确认后续没有重新插入环境原描述。

4. 空指令仍经过正常处理路径，检查词元和掩码，不替换为标准任务。

**应得到的结果:** 证明每次执行实际收到什么文本和目标的真实配对输入轨迹。

**如果没有达到预期:** 只改文件名或图注、不改策略输入，不算语言干预。

**本次完成清单**

- [ ] 扩展用例构建函数，附加指令标识、原始文本、请求物体、目标谓词，以及匹配状态和种子引用。
- [ ] 从同一场景构建标准与改变目标用例，不通过加载另一个任务更换请求物体。
- [ ] 审查序列化和分词检查，确保环境原有任务说明不会覆盖实验指令。

### 3. 用真实状态验证谓词和终止逻辑 (3 小时)

**位置：** 编码电脑：编写目标选择。运行电脑：用真实状态验证原生谓词及完成原目标后继续执行。

**详细操作步骤**

1. 把请求物体和篮子区域映射为原生谓词参数，将目标选择与物理几何计算分离。

2. 使用隔离的真实仿真状态：两者未放入、A 已放入、B 已放入，逐一检查两种谓词并保留输出。

3. 在请求 B 的开发回合中观察完成 A 后旧任务终止信号，验证连接层继续 B，同时仍尊重真实仿真故障和明确上限。

4. 每个执行步骤计算相关物体谓词，记录首次满足的集合；多目标同时首次出现时明确保留并列。

**应得到的结果:** 评分真值表，以及旧目标不会结束替代目标回合的真实执行证据。

**如果没有达到预期:** 不能通过丢弃所有终止事件修复旧目标终止，先检查来源并区分完成和故障。

**本次完成清单**

- [ ] 使用 LIBERO 现有谓词实现请求目标选择，评估识别首次完成所需的相关物体入篮目标。
- [ ] 确认重置时两个目标均为假，利用已知正例仿真状态验证放入 A 或 B 仅满足对应谓词。
- [ ] 审查环境边界，确保完成旧目标不会结束改变目标回合，并明确记录同时首次完成的多个目标。

### 4. 检查配对失败并记录结论 (2 小时)

**位置：** 编码电脑：检查返回的原指令/改变目标配对；任何新受控检查在目标执行。

**详细操作步骤**

1. 选择一对同场景原始/改变目标开发回合。

2. 先核对状态、词元、动作、首个满足物体谓词、最终目标结果和结束原因，再结合视频解释。

3. 写出有证据的分类：选错目标、无法操作预期物体，或评分/执行错误。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 能把观察与具体模型或流水线行为联系起来的失败诊断。

**如果没有达到预期:** 归因为语言之前，应先纠正不同物理场景或不匹配采样种子。

**本次完成清单**

- [ ] 结合状态、文本、动作、谓词和视频检查一对原始/改变目标开发回合。
- [ ] 用具体证据将结果归为目标选择错误、操作失败或评分/执行错误。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 运行并审查开发条件矩阵 (2 小时)

**位置：** 运行电脑：执行开发矩阵。编码电脑：审查返回配对、指令和评分证据。

**详细操作步骤**

1. 只在开发状态运行允许的开发条件，最终模板和状态不参与调参。

2. 建立配对审查视图，列出状态指纹、策略种子、实际文本、请求目标、首个物体、最终成功和结束原因。

3. 行为意外相同时，先确认文本确实进入模型、评分器确实正确改变。

4. 保存成功与失败证据，准备下一周手工指标计算所需真实记录。

**应得到的结果:** 配对有效、没有依赖最终测试筛选措辞的开发语言结果。

**如果没有达到预期:** 改写成功率高仍不足够，应检查改变目标响应及依赖场景惯性的可能。

**本次完成清单**

- [ ] 只在开发状态上运行标准、训练改写、改变目标和空指令条件。
- [ ] 检查配对初始状态哈希与策略采样种子一致，指令及请求目标字段按设计变化。
- [ ] 保存实际指令和分词检查，最终测试模板与最终初始状态不参与开发执行。
