# 第 3 周：可复现重置与动作执行步数练习

[English](week-03.en.md) | [简体中文](week-03.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 建立匹配的开发回合，并理解两次观测之间执行更多动作会产生什么影响。

**开始开发:** 已编写第 2 周回合循环及重置/动作接口；依赖真实轨迹的工作等待目标证据。

**运行电脑前置条件:** 第 2 周已完成回合循环，能够保存观测、动作和结果。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

理解目标：

- 列出比较前应控制的仿真器、稳定步骤、随机数、处理器及策略状态。
- 解释相同整数种子或相似图像为何不能证明恢复状态相同。
- 在配对轨迹定位最早分歧，解释缩短动作执行步数如何在不改权重时改变重规划。

## 准备与学习

- 阅读固定版本环境如何恢复初始状态、如何在重置后让物理系统稳定，区分随机种子与显式仿真状态。
- 检查跨调用保留的全部策略状态，包括动作队列和模型缓存。
- 理解随机动作采样、稳定步数和渲染设置为何影响可重复性。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **显式状态恢复。** 扩展仿真边界，保存并恢复指定序列化初始状态，不依赖自动推进的重置索引。分离可迁移任务/状态标识、内容哈希与目标本地路径解析，验证状态属于预期任务，记录稳定顺序及策略实际看到的起始观测。
2. **完整重置步骤。** 实现明确的回合起始顺序，覆盖仿真状态、稳定步骤、策略/模型缓存、动作队列、两个处理流水线及采样随机数。状态恢复和观测保存顺序保持一致，返回新数据，不修改共享用例规格。
3. **比较记录与容差。** 生成结构化状态/观测/首动作块比较记录，区分精确标识检查与查看结果前确定的数值容差。报告最早不匹配字段、形状、差值和来源标识，不为得到通过标签而放宽容差。
4. **A/A 和 A/B/A 诊断。** 实现开发检查，连续恢复 A 两次，以及在无关 B 回合后恢复 A。保存输入、状态指纹、首次预测及结果，定位分歧首先出现在恢复、预处理、随机数还是策略缓存。
5. **隔离动作执行步数比较。** 为检查点执行步数及一个受支持的较短值构建匹配开发配置，固定权重、物理状态、指令、策略种子、控制频率及回合上限。测量重规划/动作块次数、执行动作、延迟和行为，产物及标识与冻结主研究分离。
6. **集成与说明。** 复用回合循环及真实轨迹验证两类诊断。在现有代码指南说明恢复顺序、全部保留状态、哈希含义、容差依据、计数行为及探索性执行步数结果，链接证据，未解释运行差异保持开放。

## 分次任务

### 1. 明确可复现开发用例 (2 小时)

**位置：** 编码电脑：设计用例字段和比较规则。运行电脑：解析/捕获真实状态并确认数值表示。

**详细操作步骤**

1. 选择少量开发状态引用，保存真实序列化仿真状态标识，而不仅是环境种子。

2. 为每例记录策略采样种子、指令、相机/控制设置、稳定步数、动作执行步数和回合上限。

3. 明确状态记录位置，区分刚加载状态与稳定后真正传给策略的观测。

4. 比较前明确必须完全相同的元数据，以及允许容差的数值；容差根据表示和受支持平台确定，不围绕想要的成功标签调整。

**应得到的结果:** 小型明确用例表和有依据的比较流程。

**如果没有达到预期:** 若包装器自动推进初始状态索引，按明确引用恢复，不假设连续重置会重复同一场景。

**本次完成清单**

- [ ] 选择少量开发初始状态，为每个用例明确指令、策略种子、稳定步骤、动作执行步数和回合上限。
- [ ] 提供受支持的状态恢复接口，并记录恢复后的状态与观测指纹。
- [ ] 比较运行前，写清哪些量应完全一致，哪些允许有依据的容差。

### 2. 验证状态恢复与策略重置 (3 小时)

**位置：** 运行电脑：执行 A/A 与 A/B/A 恢复、重置及首次预测检查；在此诊断返回差异。

**详细操作步骤**

1. 恢复 A，主动重置策略和策略随机数，保存首次观测及首次预测动作块。

2. 立即重复 A，再运行 B 后恢复 A；比较初始状态、稳定后观测、首次预测和结果。

3. 寻找最早分歧：状态不匹配发生在模型之前；输入相同而预测不同，可能涉及随机数、缓存或数值设置。

4. 修复或说明原因，再重跑相同比较，诊断过程中保持渲染、稳定步骤和执行设置不变。

**应得到的结果:** A/A 与 A/B/A 对照，以及相等或首次分歧的明确解释。

**如果没有达到预期:** 截图看起来相似不足以证明仿真状态一致。

**本次完成清单**

- [ ] 显式恢复仿真器状态并重置策略，将同一开发用例运行两次，比较初始状态、观测、首次预测和结果。
- [ ] 中间插入一个无关开发回合，再恢复原用例，检测回合之间是否泄漏状态。
- [ ] 出现差异时，先分别排查仿真器、策略随机数、动作缓存、预处理和渲染，再把两次运行视为匹配对照。

### 3. 开展动作执行步数对照 (3 小时)

**位置：** 编码电脑：预测执行步数影响并准备配置。运行电脑：在匹配开发用例上执行两种支持的步数。

**详细操作步骤**

1. 读取动作块容量和执行步数，选择原始值及一个受支持较短值，不改变权重或控制频率。

2. 预测两种值下重规划次数及可能出现的视觉纠正行为。

3. 在两种执行步数下运行相同少量开发用例，保持状态、指令、采样种子和步数上限一致。

4. 比较成功、延迟、推理次数、执行动作数和视频；仅视为开发敏感性练习，正式研究仍用原设置。

**应得到的结果:** 包含运行前预测和实测行为的配对执行步数对照。

**如果没有达到预期:** 若同时改动作块生成长度、去噪设置或物理频率，先拆分实验再解释执行步数影响。

**本次完成清单**

- [ ] 选择检查点默认执行步数和另一个受支持的较短执行步数，固定场景、指令、种子和回合上限。
- [ ] 先预测重规划频率和行为变化，再对两种设置运行少量匹配开发用例。
- [ ] 测量推理次数、执行动作数、延迟、结果和可见纠正行为，正式研究仍保留原始执行步数。

### 4. 诊断轨迹并记录结论 (2 小时)

**位置：** 编码电脑：检查返回轨迹并提出假设。新的受控执行需要新目标交接。

**详细操作步骤**

1. 选择已保存用例中的一个意外差异。

2. 找到轨迹第一次出现不同观测/动作的位置，提出一个可验证的来源假设。

3. 只改变一个开发因素重复诊断，记录什么证据会反驳你的解释。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 建立在最早分歧证据上的具体调试论证。

**如果没有达到预期:** 未检查明确状态引用和动作队列重置前，不把所有差异都归为随机性。

**本次完成清单**

- [ ] 用已保存轨迹研究一个可重复性差异，或一个与执行步数相关的行为。
- [ ] 写出具体假设，找出支持证据，并进行一次受控开发检查。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 准备实验执行器约定 (2 小时)

**位置：** 编码电脑：仅记录已验证重置约定，并根据返回证据准备清单字段。

**详细操作步骤**

1. 在环境连接层文档字符串中记录验证过的重置/稳定顺序，并保留开发对照证据。

2. 在对应的 `doc/` 双语文档总结执行步数实验，明确标为探索性研究，与正式评估分离。

3. 写出重建配对用例的最小标识信息，交给下周清单实现。

4. 验证探索性运行不会覆盖主配置，或以同一标识在不同执行步数下恢复。

**应得到的结果:** 可复现重置约定，以及探索性设置保持隔离的证据。

**如果没有达到预期:** 即便机器人偶尔成功，无法解释的状态漂移仍会阻止配对评估。

**本次完成清单**

- [ ] 在对应的 `doc/` 双语文档和代码文档字符串中保存重置流程、容差依据、开发用例标识和动作执行步数练习结果。
- [ ] 列出第 4 周清单必须保存的用例标识和运行元数据。
- [ ] 确认探索性执行步数调整和开发状态选择不会悄悄进入冻结的评估配置。
