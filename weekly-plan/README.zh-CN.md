# 每周执行与阅读计划

[English](README.en.md) | [简体中文](README.zh-CN.md)

本目录把[实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)拆分为每周实现、执行及阅读任务。各计划明确前置条件、实现范围、代码/文档阅读路径、理解目标、步骤、排错及必需证据。

复选框只记录经过验证的证据。第 1 周检查及第 2 周标准回合源码已可使用，真实目标门槛、试点执行及实验结果仍未验证。代码写好不代表运行检查完成。

## 使用方式

1. 实现本周范围前，阅读目标、前置条件及固定源码。
2. 五次任务时间仅作工作估算，无人值守 GPU 时间须按真实测量另外估算。
3. 按每周**阅读内容与理解目标**阅读：先文档、再当前源码、沿调用阅读，最后阅读本里程碑新代码/证据。清单列明文件/符号及三个理解目标；计划代码实现后替换成真实链接。
4. 第 4 次任务审查证据，并在对应 `doc/` 双语文档中说明发现。使用复核问题检查理解。
5. 每次代码变更同时更新[代码指南](../doc/CODE_GUIDE.zh-CN.md)，说明设计理由、全部已实现结构、接口、错误及验证证据。
6. 执行适用本地及真实目标检查；只有所需证据存在时才同步双语完成状态。
7. 目标门槛待验证时继续不依赖它的后续开发；依赖它的实验须等前置条件通过。

命令块注明终端及机器。安装项目本地环境，调用 API 前检查固定源码，不假定计划命令已经存在。按真实吞吐量估算长任务，超时则顺延，不跳过检查或悄悄缩减实验。

## 在两台电脑间工作

遵循[执行位置及门槛顺序](../doc/IMPLEMENTATION_PLAN.zh-CN.md#双机开发与执行)与[迁移/证据步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)。

1. 在 Windows 实现并检查可迁移工作，准备准确目标命令，固定包含必需未提交文件的审查后源码快照。
2. 已有授权访问时，迁移并核对哈希，重建 WSL 本地环境/路径，长任务前先运行最小真实集成检查。
3. 带回含运行/源码标识的报告、记录、图像/视频及轨迹，检查覆盖和错误，用已声明依赖分析可迁移数据。
4. 分别记录**开发已就绪**、**目标已验证**和双语文档。缺少运行证据时保持待完成，不编造 ID、哈希、观测或测量。
5. 无法访问目标或执行系统级操作时，记录具体阻碍及所需安装操作，保持依赖运行检查待完成，继续不依赖它的准备工作。

十二周表示依赖里程碑，目标可用时间可能使一个里程碑跨越多个日历周。

## 学习与实验边界

- 开发与调试使用开发初始状态和允许的训练/验证措辞，最终状态及最终测试模板不参与调参。
- 最终评估前固定检查点选择，开发、选择、最终和复现运行均明确标记。
- 保留异常与缺失覆盖，不编造结果、不悄悄改变控制条件，也不将部分运行宣称为研究完成。
- 在 `doc/` 双语文档中维护当前设计/代码说明；实验证据与概念笔记分开保存。
- 本周期不增加仪表盘、其他模型家族、实体硬件、强化学习或自动发布。
- 除非明确要求提交，否则改动保持未提交状态。

## 完成要求

软件、证据、复现及双语文档验收均通过后，项目才算完成。可复现的负面微调结果是有效成果；原因不明或未完成的流水线不能作为这种结果的证据。
