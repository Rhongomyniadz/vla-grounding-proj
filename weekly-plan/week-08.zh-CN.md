# 第 8 周：示范数据与经过验证的 LoRA 冒烟训练

[English](week-08.en.md) | [简体中文](week-08.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**目标:** 准备公平的仅语言变化微调数据，并在完整训练前验证训练与检查点生命周期。

**开始条件:** 两个评估后端可用，开发分析有效，训练/验证/最终指令模板家族已固定。

时间预算：五次学习共十二小时主动投入，其中一小时关闭智能体独立完成；电脑运行时间另计。

## 准备与学习

- 阅读实施计划中的数据划分、归一化约定和共享 LoRA 配置，以其作为参数唯一依据。
- 通过 LeRobot 加载器检查真实示范的图像、状态、动作、时间戳、回合标识和任务指令。
- 学习行为克隆/动作预测、冻结主干与可训练适配器的区别，以及为何不能用改变目标指令重标注未变化示范。

## 分次任务

### 1. 检查数据并明确划分 (2 小时)

- [ ] 你：检查四个主要任务的样本，解释状态、图像和动作如何在时间上对齐。
- [ ] 使用固定数据集版本，按约定以完整回合进行任务分层划分，保留原始回合标识。
- [ ] 验证示范没有跨集合重复，并区分示范留出集与独立仿真初始状态评估留出集。

### 2. 准备两份训练副本 (3 小时)

- [ ] 智能体：从同一训练划分制作项目自有副本，只在这些副本上使用受支持的 LeRobot 任务重标注工具。
- [ ] 你：在每个任务内近似均匀分配标准指令及四个训练改写模板，每个回合只对应一条一致指令。
- [ ] 验证两组数值观测、动作、帧数、顺序和检查点归一化相同，替代物体指令不能配给错误示范。

### 3. 验证可训练参数与检查点行为 (3 小时)

- [ ] 智能体：按共享配置接入固定版本上游训练器与 LoRA，使用 BF16 接口、明确本地输出并关闭上传。
- [ ] 你：检查可训练参数列表，确认目标主干保持冻结，解释训练目标实际比较什么。
- [ ] 执行计划中的一百次更新冒烟检查，保存并重载检查点，使用恢复后的处理流水线运行开发回合。

### 4. 独立审查训练样本后再复核 (2 小时)

- [ ] 前一小时关闭智能体，追踪一个样本从源回合经过重标注、分词、归一化到动作监督目标的过程。
- [ ] 验证指令描述了记录动作，且该样本属于预期数据划分。
- [ ] 后一小时与智能体审查样本追踪及冒烟故障，在完整训练前解决根本原因。

### 5. 固定共享训练配置 (2 小时)

- [ ] 保存划分映射、源版本、指令分配、副本对照证据、归一化标识及实测更新耗时和显存。
- [ ] 若资源或数值问题需要调整配置，应在任何完整训练开始前显式同步修改两组。
- [ ] 根据实测值估算两组完整训练和检查点选择评估成本，最终测试用例保持未使用。

## 证据与完成检查

- [ ] 源回合到划分的映射互不重叠，两组训练数据仅存在预期语言标签差异。
- [ ] 已检查可训练模块、冻结参数、归一化和样本/动作对齐。
- [ ] 真实一百次更新检查点能够保存、重载并运行，共享配置和实测资源预算已固定。

## 关闭智能体后解释

1. 为什么更改示范文本中的目标物体通常会破坏动作标签的有效性？
2. 改变归一化为何会混淆原本只改变语言的对照？
3. 训练损失降低能证明什么，为什么不能证明目标选择更准确？

## 给编程智能体的建议请求

> 准备两组数据副本和上游 LoRA 冒烟训练，展示可训练参数及样本追踪，由我验证标签和干预依据。

## 进入下一周的条件

仅在数据等价性、参数选择、有限数值更新、检查点重载及重载后真实执行都通过验证后，才开始完整训练。
