# 第 8 周：示范数据与经过验证的 LoRA 冒烟训练

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 准备公平的仅语言变化微调数据，并在完整训练前验证训练与检查点生命周期。

**开始开发:** 已明确数据集接口、模板家族和共享配方；目标验证前可编写划分/重标注及训练集成。

**运行电脑前置条件:** 两个评估后端可用，开发分析有效，训练/验证/最终指令模板家族已固定。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

3. **带回审查：** 带回来源/划分哈希及数量、指令分配、数值等价检查、真实处理后批次摘要、可训练参数、有限更新日志、重载执行和目标耗时/显存。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

理解目标：

- 解释整回合划分隔离及源到派生 ID 映射，区分示范留出与仿真状态留出。
- 追踪一个样本从指令分配、词元、归一化到动作监督，解释改变目标重标注为何无效。
- 解释冻结/可训练参数、标准指令对照、相同预算及 100 次更新后保存/重载/执行证据。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **固定数据检查与来源。** 接入真实 LeRobot 加载器读取选定任务示范，记录不可变数据集标识。检查图像/状态/动作/时间对齐，保留原始回合 ID、任务标识及帧范围，使每个派生样本可追溯。
2. **整回合划分。** 按权威方案实现确定性任务分层划分，保存源到派生回合映射及逐任务成员/数量，拒绝重叠、缺标识和按帧泄漏。示范留出与仿真状态评估留出分开。
3. **项目自有训练副本。** 生成一次训练划分，再从中派生标准/改写副本。仅对这些副本使用受支持数据工具应用冻结指令分配，每回合保持一条一致指令，不修改下载源。
4. **仅语言差异核对。** 通过真实加载器比较两副本，覆盖数值观测/动作、帧数、媒体、回合顺序、样本/动作块对齐及检查点归一化。只允许预期语言元数据差异，验证真实处理批次使用分配文本且排除验证/最终模板。
5. **上游 LoRA 集成。** 使用共享配置及固定训练器/PEFT 接口准备明确本地训练配置，包括受支持 BF16 机制。审查可训练参数名/大小、冻结主干、优化器/调度、基础/处理器标识及关闭上传/追踪，不另写训练循环。
6. **有界训练生命周期与文档。** 执行规定冒烟更新，验证有限损失及预期参数变化，连同处理器保存检查点，在新进程重载并运行真实开发回合。测量更新时间/显存，完整训练前说明划分/重标注函数、等价校验、LoRA 选择、检查点流程及任何共享配置修正。

## 分次任务

### 1. 检查数据并明确划分 (2 小时)

**位置：** 编码电脑：设计划分/来源逻辑。运行电脑：检查真实示范并生成经过验证的完整回合划分。

**详细操作步骤**

1. 加载固定源数据，检查每个主要任务真实回合中的指令、相机、状态、动作、帧号和时间戳。

2. 选择短区间，解释哪一观测条件对应动作监督，以及动作块接近回合边界时会怎样。

3. 按计划在完整回合层面任务分层划分，保存原回合到派生回合标识映射。

4. 核对互斥成员、各任务数量和标签一致性，将示范留出与仿真初始状态留出区分。

**应得到的结果:** 经过验证的划分映射，以及能解释观测/动作对齐的真实样本。

**如果没有达到预期:** 复制导致编号改变时比较原身份映射，不把重新编号当成不同数据的证据。

**本次完成清单**

- [ ] 检查四个主要任务的样本，解释状态、图像和动作如何在时间上对齐。
- [ ] 使用固定数据集版本，按约定以完整回合进行任务分层划分，保留原始回合标识。
- [ ] 验证示范没有跨集合重复，并区分示范留出集与独立仿真初始状态评估留出集。

### 2. 准备两份训练副本 (3 小时)

**位置：** 编码电脑：实现分配和比较逻辑。运行电脑：仅复制/重标注项目数据，通过真实加载器验证两组。

**详细操作步骤**

1. 先生成一份实际训练划分，再由同一材料生成两个项目自有副本，不修改下载源。

2. 对照组使用标准措辞，改写组按计划混合标准/训练改写，每任务内近似平衡。

3. 通过受支持任务编辑同步帧任务索引与回合/任务元数据，再用真实加载器检查，而不只看文本。

4. 比较两组数值样本、媒体、回合顺序、动作块和归一化标识，只允许预期语言元数据差异。

**应得到的结果:** 真实加载器验证过、能证明仅语言不同的两组训练数据。

**如果没有达到预期:** 把替代物体指令配给原物体动作是错误监督，不是有效改写增强。

**本次完成清单**

- [ ] 从同一训练划分制作项目自有副本，只在这些副本上使用受支持的 LeRobot 任务重标注工具。
- [ ] 在每个任务内近似均匀分配标准指令及四个训练改写模板，每个回合只对应一条一致指令。
- [ ] 验证两组数值观测、动作、帧数、顺序和检查点归一化相同，替代物体指令不能配给错误示范。

### 3. 验证可训练参数与检查点行为 (3 小时)

**位置：** 编码电脑：按固定接口准备训练配置。运行电脑：检查参数，执行 100 次更新及保存/重载/回合。

**详细操作步骤**

1. 按冻结配置接入上游训练器，检查固定版本如何接受目标 BF16 设置，不编造新版本参数。

2. 列出可训练参数名和大小，按实际 PEFT 定义核对适配器/投影与冻结主干。

3. 执行有界冒烟训练，检查有限损失、梯度、优化更新、显存及预期参数确实改变。

4. 保存后在新进程用保存处理器和精确基础模型标识重载，再执行开发回合；只加载权重不算完整检查。

**应得到的结果:** 参数选择、预处理和执行均已验证的真实冒烟检查点。

**如果没有达到预期:** 不要求每个适配器在首步梯度非零，应检查总体预期更新、初始化和损失。

**本次完成清单**

- [ ] 按共享配置接入固定版本上游训练器与 LoRA，使用 BF16 接口、明确本地输出并关闭上传。
- [ ] 检查可训练参数列表，确认目标主干保持冻结，解释训练目标实际比较什么。
- [ ] 执行计划中的一百次更新冒烟检查，保存并重载检查点，使用恢复后的处理流水线运行开发回合。

### 4. 审查训练样本并记录结论 (2 小时)

**位置：** 编码电脑：追踪返回样本/批次来源。加载器或分词检查需在目标执行，除非此处已声明相应依赖。

**详细操作步骤**

1. 从改写副本选择一个样本，找到源回合及产生文本的分配规则。

2. 追踪加载指令的分词过程，以及数值输入和监督目标的归一化。

3. 验证请求物体/目的位置描述了示范，且最终评估模板没有进入训练。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 文本、数值目标、归一化与划分相符的样本级证据。

**如果没有达到预期:** 元数据看似正确不证明训练器实际使用，应检查真实处理后批次。

**本次完成清单**

- [ ] 追踪一个样本从源回合经过重标注、分词、归一化到动作监督目标的过程。
- [ ] 验证指令描述了记录动作，且该样本属于预期数据划分。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 固定共享训练配置 (2 小时)

**位置：** 编码电脑：审查证据并准备两组完整运行。全部成本估计和配方修订依据真实目标实测。

**详细操作步骤**

1. 保留源版本、划分映射、模板分配、加载对照、可训练参数证据和冒烟运行元数据。

2. 用启动后实测更新耗时估算完整训练，不按模型大小或其他 GPU 基准猜测。

3. 显存/数值问题需调整设置时，在任何完整组启动前明确修改共享配置并同步双语架构文档。

4. 固定训练命令/配置，为两组完整运行准备同一初始检查点。

**应得到的结果:** 真实加载、梯度、检查点及资源验证支持的可复现共享配置。

**如果没有达到预期:** 不能为了跑通只降低一组批量、更新次数或改变归一化。

**本次完成清单**

- [ ] 保存划分映射、源版本、指令分配、副本对照证据、归一化标识及实测更新耗时和显存。
- [ ] 若资源或数值问题需要调整配置，应在任何完整训练开始前显式同步修改两组。
- [ ] 根据实测值估算两组完整训练和检查点选择评估成本，最终测试用例保持未使用。
