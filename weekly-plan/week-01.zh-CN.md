## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **环境配置与安装。** 完善 `pyproject.toml`、`uv.lock` 和 `configs/week-01.json` 中现有项目本地依赖/配置，分离 Windows 开发依赖和 WSL 运行依赖，明确要求硬件、任务、相机/控制及版本输入。保留安装错误，验证真实目标解释器，不把锁解析成功当作安装证据。
2. **平台与 CUDA 检查。** 保持开发与目标检查为独立命令入口，导入 ML 依赖前校验必需设置，再验证目标系统/文件系统、存储、包版本、预期 GPU 及真实 CUDA 运算。保存机器相关报告，明确哪些已通过、哪些仍未验证。
3. **资源解析与仿真引导。** 完善不可变快照下载，包含有限网络重试、结构化警告及必需快照字段。仿真导入前重建目标本地 LIBERO/EGL 配置和资源链接，拒绝缺快照、路径冲突及不兼容解释器，不替换成其他环境。
4. **仿真器与策略接口。** 使用固定上游 API 完善检查点加载、显式相机键映射、观测准备、处理器重置及动作解码。在边界校验双相机、机器人状态、语言张量、预测块及执行动作。现有有界上游冒烟仍仅用于接口检查。
5. **观测检查与证据。** 使用并验证现有检查函数，输入明确，以强类型记录返回形状、类型、有意义的范围及有限状态。对真实保存的原始/处理后数组执行检查，词元和掩码与连续张量分开处理。保留对齐相机图像、诊断预测、执行动作，以及能完整解码的 MP4。
6. **验证与文档。** 执行现有开发命令检查，目标可访问时按 CUDA → 资源 → 相机 → 策略/视频验证。视频内容检查与解码分开记录。在环境及代码指南更新已验证命令、模块/函数职责、导入顺序、张量转换和真实证据链接；无法执行的目标检查保持待完成。

## 分次任务

### 1. 确认目标电脑并预测数据流 (2 小时)

**位置：** 编码电脑：画数据流草图。运行电脑：收集真实 Windows 主机和 WSL 清单。

**详细操作步骤**

1. 在 RTX 5080 Windows 主机打开 PowerShell，运行下列诊断命令，记录真实 GPU 和 Ubuntu 发行版，不沿用其他电脑的清单。

   ```powershell
   nvidia-smi
   wsl --list --verbose
   ```

2. 进入目标 Ubuntu，运行 `uname -a`、`cat /etc/os-release`、`pwd -P`、`df -h .`、`free -h`，说明哪些输出对应 Linux、可用资源和当前文件系统。

3. 在目标 WSL Linux 文件系统选择运行工作目录。编辑器位于编码电脑：使用统一交接步骤，确认执行终端实际使用哪份源码快照，并重建目标环境。

4. 在对应的 `doc/` 双语文档画出观测、预处理、策略、解码动作、控制器和下一观测六个框，在箭头下写明经过的数据。

**应得到的结果:** 真实电脑清单，以及带有逐项说明、明确标出未知概念的数据流图。

**如果没有达到预期:** 如果发行版不是 WSL2 或 GPU 不是目标设备，先修正环境，再下载模型资源。

**本次完成清单**

- [ ] 记录目标 GPU、可用内存与存储、Windows/WSL/Ubuntu 版本，以及 Linux 项目文件的存放位置。
- [ ] 在代码指南画出观测到动作的数据流，并说明每个表示及转换。
- [x] 检查固定版本的上游安装要求，提出仅运行仿真所需的最小环境配置。

### 2. 搭建并验证基础环境 (3 小时)

**位置：** 编码电脑：审查依赖并运行开发检查。运行电脑：安装运行环境并验证 CUDA/资源/EGL。

**详细操作步骤**

1. 在项目配置中声明仅仿真所需依赖，采用实施计划初始版本基线和固定源码兼容约束，先审查依赖声明再解析安装。

2. 按环境指南中的目标侧安装部分在 WSL 创建项目环境，检查解释器路径，并使用明确的 `.venv/bin/` 命令。锁文件已完成解析，但 Linux 安装本身仍待验证，要保留解析或安装报错。编写代码电脑上能导入不算验证。

3. 完成声明依赖的安装后，从经过核对的目标检出目录使用明确解释器运行：

   ```bash
   .venv/bin/python -c "import sys, torch; print(sys.executable); print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available())"
   .venv/bin/python -c "import torch; x=torch.ones((32,32),device='cuda'); print((x@x).mean().item()); print(torch.cuda.get_device_name(0))"
   ```

4. 执行环境指南中已实现的资源下载和渲染命令。继续前检查不可变资源清单及生成的 LIBERO 配置。引导代码在导入仿真器前设置路径和 EGL，渲染命令无需策略权重即可生成两路画面。保存图像及报告作为证据。

**应得到的结果:** 目标解释器能执行真实 CUDA 运算，仿真器产生两张可检查图像。

**如果没有达到预期:** 分别排查驱动/WSL、Python 安装包、资源路径和渲染器，不用切换 CPU 隐藏渲染失败。

**本次完成清单**

- [ ] 按约定版本和受支持接口，实现可复现依赖安装、CUDA 检查及无界面渲染检查。
- [ ] 在 WSL 中执行检查，查看两路相机画面，确认报告的设备是目标 RTX 5080。
- [ ] 发生错误时保存原始命令和报错，定位失败层次，验证针对根本原因的修复后再继续。

### 3. 加载检查点并检查真实预测 (3 小时)

**位置：** 运行电脑：加载检查点、检查真实张量并执行策略冒烟；在此检查返回摘要/视频。

**详细操作步骤**

1. 复用第 2 次学习生成的资源清单，其中记录检查点、VLM/分词器与仿真快照。同一次运行不要重新下载可变引用。加载前确认本地快照路径属于目标电脑。

2. 输出检查点输入输出特征名，逐一与真实仿真观测比较，配置明确的源键到策略键映射。

3. 检查处理后图像、状态、词元和语言掩码，在原始表示旁记录实际形状与范围，确认预期指令通过分词。

4. 运行指南中已实现的策略冒烟命令；它复用上游轨迹函数，作为初始接口检查。结合 `smoke.json` 检查 `prediction.npz`、`executed-actions.npz` 和短视频。命令核对首次解码预测与首次实际执行动作一致，仅用于接口检查，不作为任务成功率测量。

**应得到的结果:** 从真实原始输入到实际解码动作的可追踪示例，以及可播放冒烟视频。

**如果没有达到预期:** 形状看似正确但运动异常时，先检查相机顺序、状态构造、动作归一化和控制模式，不先改策略。

**本次完成清单**

- [ ] 通过小型连接层提供检查点加载和观测预处理，记录第 2 周回合循环所需接口。
- [ ] 检查原始及处理后的图像/状态形状、分词结果与掩码、特征映射、归一化器、预测动作块及执行动作维度。
- [ ] 使用已有上游冒烟检查或评估接口获得预测、执行仿真步进并保存可播放短视频，记录解析后的资源版本。
