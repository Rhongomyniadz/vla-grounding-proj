# 第 12 周：复现、展示与代码说明审查

[English](week-12.en.md) | [简体中文](week-12.zh-CN.md)

[每周计划索引](README.zh-CN.md) | [实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md)

**文档：** 同步更新[双语代码指南](../doc/CODE_GUIDE.zh-CN.md)，覆盖本周设计理由、已实现结构及验证证据。

**目标:** 交付可审阅、可复现作品集及完整双语设计/代码说明。

**开始开发:** 已知复现/作品集约定；可提前起草步骤，最终复现及文档检查依赖第 11 周证据。

**运行电脑前置条件:** 第 11 周已具备有证据支持的报告、最终图表、带注释案例和保留的实验产物。

工作估算：五次任务共十二小时主动工作，包含证据审查及文档。GPU 运行时间另计并按实测安排。

## 执行位置

使用[统一交接步骤](../doc/ENVIRONMENT.zh-CN.md#每次访问运行电脑时的交接)，下方每次学习的位置约束详细操作。

1. **在编码电脑准备：** 准备复现清单、文档命令、作品集链接及完整源码到指南审查，保留原冻结研究。
2. **在运行电脑执行：** 在同一运行电脑创建全新隔离环境，验证 CUDA/相机/处理器并复现代表性比较；仅开发用循环改动也在此执行。
3. **带回审查：** 带回全新环境源码/锁文件/后端标识、安装和运行日志、参考与复现对照及视频，在此结合作品集和文档覆盖检查。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

## 阅读内容与理解目标

按以下顺序阅读。尚不存在的源码会明确标注；完成本里程碑前，将计划代码描述替换为实际文件/符号链接，并补充对应证据引用。

| 顺序 | 必读内容 |
| --- | --- |
| 1. 文档 | [环境指南](../doc/ENVIRONMENT.zh-CN.md)：全新安装/迁移准确命令。[实施计划](../doc/IMPLEMENTATION_PLAN.zh-CN.md#5-验证与完成标准)：软件、说明及作品集门槛。完整阅读[代码指南](../doc/CODE_GUIDE.zh-CN.md)及交付后的最终双语结果报告。 |
| 2. 当前代码 | [pyproject.toml](../pyproject.toml)、[config.py](../src/vla_grounding/config.py)、[assets.py](../src/vla_grounding/assets.py)、[bootstrap.py](../src/vla_grounding/bootstrap.py)、[runtime.py](../src/vla_grounding/runtime.py)：复现环境及标识。 |
| 3. 沿调用阅读 | 按代码指南阅读所有实际回合/用例/评分、执行/恢复、指标、数据/训练及选择模块，不假设文件布局。 |
| 4. 本里程碑代码/证据 | 复现清单/比较代码及产物链接在实现后阅读，按记录容差比较原环境与全新环境证据。 |

理解目标：

- 在源码定位每项职责，讲清完整指令到动作再到结果路径。
- 解释复现面板为何是代表性检查而非新一轮完整套件，并诊断最早分歧。
- 按文档输入及证据找回展示结果，说明剩余局限及有依据的下一项实验。

## 准备与学习

- 以新贡献者视角阅读安装/运行说明，找出只存在于个人终端或记忆中的假设。
- 复核实施计划中的全部交付验收要求，选择有代表性的小型复现面板。
- 区分复现配置与测量行为，以及承诺跨不同运行环境得到逐位一致 GPU 结果。

## 阅读路线与理解目标

- 把[软件与说明验收](../doc/IMPLEMENTATION_PLAN.zh-CN.md#5-验证与完成标准)视为真实退出条件，而不是事后庆祝。
- 假设从未用过项目，阅读 README 验证过的安装/运行命令，找出终端、路径、环境和资源假设。
- 复核前面建立的用例标识、数值容差和产物链路，使复现有明确比较对象。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **全新环境复现步骤。** 使用锁定依赖及不可变源码/模型/数据/资源，在全新隔离环境完成文档安装流程，保留已有可用环境、检查点及最终证据。记录全部真实安装命令，在现有环境指南修正缺失路径/环境假设。
2. **代表性复现清单。** 根据保存标识为每个策略构建约定的小型原始/改变目标和鲁棒性比较。启动前校验源码、任务/状态/变体、指令、种子、后端、处理器和执行设置，复现运行与最终评估明确分离。
3. **参考与重跑比较。** 实现或完善比较函数，覆盖恢复状态、输入、预测/执行动作、目标信号、停止原因、元数据和汇总指标。使用事先有依据的容差，报告最早分歧；归因于数值变化前排查安装/随机数/缓存。
4. **作品集整理与产物审查。** 用真实图表、注释视频、可复现命令/证据链接完善 README/报告讲解。核对全部展示结果标识及输出可找回性，通过记录位置访问目标大型产物，不自动提交或发布。
5. **完整代码/文档覆盖。** 列出全部已实现模块、命令、记录、类及函数，与双语代码指南核对。解释关系、输入输出、非简单控制流、校验/错误、设计权衡及验证状态；已存在实现的计划阅读条目替换为真实源码/符号链接。
6. **最终验收与局限。** 按真实证据核对软件检查、最终覆盖、复现差异、文档链接/翻译及周进度。交付代表性比较记录，必要时明确剩余缺口。记录有依据的未来实验，不新增核心功能或改变冻结主张。

## 分次任务

### 1. 准备全新复现环境 (2 小时)

**位置：** 编码电脑：审查/迁移复现快照。运行电脑：创建全新基础/分支环境，不删除工作环境，再执行输入/环境门槛。

**详细操作步骤**

1. 记录原可用环境和产物位置，新建项目环境，不移除原环境。

2. 严格遵循 README 已验证的依赖/配置流程，使用锁定版本及不可变模型/数据/资源引用。

3. 发现文档遗漏手动步骤时修改对应现有说明，不新建独立安装日记。

4. 重新执行环境和输入约定检查，确认新环境解析到相同预期处理器及后端资源。

**应得到的结果:** 按文档输入创建的新环境，遗漏安装假设已修正。

**如果没有达到预期:** 不能借用未记录全局包或不记版本变化来让复现通过。

**本次完成清单**

- [ ] 新建项目环境，不删除当前可用环境、数据集、检查点或最终产物。
- [ ] 使用锁定依赖及不可变源/资源引用，再次验证 CUDA、两路相机、策略输入和处理流水线标识。
- [ ] 严格按文档执行，找出缺失的环境变量、路径、资源或未说明手动步骤。

### 2. 复现有代表性的对照 (3 小时)

**位置：** 运行电脑：执行代表性复现面板。编码电脑：比较返回参考、动作、状态和结果。

**详细操作步骤**

1. 建立声明的小型复现清单，对每策略包括原始/改变目标对照及一个鲁棒性用例。

2. 运行后与保存参考比较标识、指令、恢复状态/变体、输入、解码动作、结束原因和指标。

3. 归因数值不确定前寻找最早分歧，检查依赖、渲染、设备、种子、队列重置及状态恢复。

4. 报告复现范围与剩余差异，小型检查不等于再次完整评估最终套件。

**应得到的结果:** 参考与复现之间具体可比较、差异可解释的记录。

**如果没有达到预期:** 不能看过结果后放宽容差，只为标为复现成功。

**本次完成清单**

- [ ] 为三个策略分别运行包含一对原始/改变目标回合和一个鲁棒性用例的小型明确面板。
- [ ] 与保留记录比较恢复状态/变体标识、实际指令、预测/执行动作、评分、元数据和结果。
- [ ] 结合已记录数值容差及运行细节排查差异，说明剩余可复现性局限，不宣称重跑了全套实验。

### 3. 完成作品集讲解 (3 小时)

**位置：** 编码电脑：准备讲解，审查文档/产物链接，保留访问目标所存大证据的方式。

**详细操作步骤**

1. 准备简明书面讲解：问题、数据流、受控对照、结果、局限和未来实验。

2. 选择支持量化结论的已有注释案例，包含有意义失败或负面证据。

3. 验证 README/报告链接、命令、产物引用及输出可找回性。

4. 保持可审阅：用 `git status --short` 看状态，用 `git --no-pager diff` 审查已跟踪改动，直接检查未跟踪文件，不自动发布或提交。

**应得到的结果:** 他人能够从仓库追踪到真实证据的作品集讲解。

**如果没有达到预期:** 精美视频若无用例标识与配置，只是展示，不是可复现结果。

**本次完成清单**

- [ ] 准备简短讲解，覆盖研究问题、系统数据流、对照设计、主要发现和局限。
- [ ] 协助将已有图表、带注释视频、产物链接和验证过的安装/运行命令整理进 README 和报告。
- [ ] 核实所有展示结果真实且有标签，生成产物可找回，不自动发布或提交。

### 4. 审查全部代码结构及其说明 (2 小时)

**位置：** 编码电脑：核对实际源码及双语指南；缺失运行证据从目标获取。

**详细操作步骤**

1. 列出实际源码中所有项目自有模块、命令、模型、类及函数。
2. 逐项匹配双语代码指南，核对职责、输入输出、相互关系、错误、设计理由及验证状态。
3. 分别用一个真实证据包追踪回合循环、用例/评分、指标及训练流水线，补充说明与失效链接，不改变冻结研究条件。
4. 将周阅读路径更新为实际实现文件/符号，核对翻译，列出尚未解决的运行问题。

**应得到的结果:** 完整源码到指南覆盖审查，以及可重复使用的阅读路径。

**如果没有达到预期:** 缺代码或运行证据必须明确保持计划/待完成；文档不能替代实现或测量。

**本次完成清单**

- [ ] 将全部已实现模块、命令、记录、类及函数匹配到双语指南。
- [ ] 核对设计理由、控制/数据流、接口/错误约定及真实证据链接。
- [ ] 修正缺失/过期说明及周阅读路径，保持未解决证据门槛待完成。

### 5. 完成说明与仓库最终审查 (2 小时)

**位置：** 编码电脑：检查全新目标复现证据后，完成最终说明/文档审查。

**详细操作步骤**

1. 记录并解释完整感知到动作路径、配对评分、指标分组、训练对照及一次失败诊断。

2. 按真实证据检查里程碑，不受支持的完成框在两种语言中均保持未选。

3. 核对新环境复现、结果覆盖、报告主张、双语一致性及产物/文档链接。

4. 把下一合理研究问题记为未来工作，保留当前研究范围和未提交审阅状态。

**应得到的结果:** 有证据的完整项目及双语说明，或明确的剩余缺口列表。

**如果没有达到预期:** 负面微调结果可以完整，但无法解释的坏流水线或缺失最终证据不能冒充该结果。

**本次完成清单**

- [ ] 梳理完整指令到动作回合，解释配对目标评分及微调对照，并诊断一个已保存失败。
- [ ] 检查文档链接、双语对应、每周清单状态、复现证据和报告一致性，未完成项保持明确未勾选。
- [ ] 将有依据的下一项实验记录为未来工作，同时保留当前项目范围、证据和未提交审阅状态。

## 证据与完成检查

- [ ] 文档已就绪：双语设计/代码指南覆盖全部已实现结构、理由、接口及验证状态。
- [ ] 开发已就绪：本周源码/配置及适用本地检查已包含在明确标识的交接中。
- [ ] 目标已验证：所需真实目标证据已返回，并按该交接完成审查。
- [ ] 全新环境能执行文档中的代表性对照，并解释复现差异。
- [ ] 作品集链接到已验证安装、真实结果、不确定性、注释案例和明确局限。
- [ ] 双语指南覆盖全部已实现结构，并有据解释系统、实验、指标及结论。

## 可选复核问题

1. 能否在源码定位每个核心职责，并解释输入如何变成输出？
2. 什么证据会改变你的主要结论，你会如何设计下一项实验？
3. 其他人能否只凭仓库和引用产物复现一项选定对照？
