3. **带回审查：** 带回两套解释器/导入/路径清单、固定后端/资源标识、冻结变体/参考清单、状态对照、试点结果/图像/视频和基础环境复查。

无法访问目标时，保留真实运行检查待完成，记录具体访问或安装阻碍，准备准确交接并继续不依赖目标证据的开发。

- 解释共用命名空间时，独立环境为何不自动证明配置/资源隔离。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **隔离鲁棒性安装。** 声明并构建独立项目环境，使用固定 LIBERO-plus 代码/资源，不替换基础环境。通过受支持接口配置独立运行/资源路径，记录解释器、导入和配置位置，安装后重跑基础冒烟。
2. **鲁棒性连接层。** 将既有观测、预处理、相对控制及请求目标约定适配到分支，校验真实相机/状态/动作特征，每条用例/结果保留后端/版本标识。缺资源或接口不受支持时明确报错，不替换后端。
3. **元数据解析与面板构建。** 读取已安装任务/类别定义，将每个变体对应到已验证主要任务，按真实套件成员解析运行索引，校验物体/目标/状态引用，按方案确定性采样，不根据策略结果选择变体。
4. **无扰动参考构建。** 在同一鲁棒性后端用固定原始定义/状态构建参考用例，明确关联任务、变体、参考及策略采样控制。相机比较验证物理部分不变；布局状态已改变时如实说明，不在不支持时宣称精确匹配。
5. **开发试点与覆盖。** 分别执行相机/布局开发试点，保留对齐初始图像、物理状态、动作、谓词及视频。生成并冻结最终面板覆盖清单供后续评估，试点结果与最终面板证据分离。
6. **隔离审查与说明。** 全部安装修改后验证两环境仍解析到各自代码/配置/资源。在代码指南说明分支连接层、元数据到索引映射、采样函数、参考关系及比较局限，链接真实导入/状态/渲染诊断。

## 分次任务

### 1. 明确后端隔离与比较规则 (2 小时)

**位置：** 编码电脑：明确隔离及支持的路径设置。运行电脑：创建独立分支环境，验证导入/资源并复查基础环境。

**详细操作步骤**

1. 保留可用基础环境，为分支建立独立项目环境，记录两侧解释器、导入包位置和版本。

2. 检查各安装如何解析配置及资源路径；上游提供 `LIBERO_CONFIG_PATH`，依赖该设置前先核实选定分支实现。

3. 通过受支持机制配置独立运行路径，渲染前输出解析后的任务、资源和初始状态位置。

4. 分支配置后重跑基础冒烟用例，确认没有把基础资源重定向。

**应得到的结果:** 分别验证的导入/配置/资源路径，以及仍能工作的基础冒烟用例。

**如果没有达到预期:** 仅有独立 Python 环境，不能证明共享用户配置文件已被隔离。

**本次完成清单**

- [ ] 使用受支持配置机制准备独立 LIBERO-plus 环境，固定依赖、代码和资源版本。
- [ ] 验证两个环境分别导入预期包，并解析到正确资源和初始状态文件。
- [ ] 写清哪些相机用例能共享物理状态，以及布局比较为何需要明确的变体状态。

### 2. 创建并检查变体清单 (3 小时)

**位置：** 编码电脑：实现映射/采样代码。运行电脑：解析已安装元数据/状态标识，冻结独立于性能的清单。

**详细操作步骤**

1. 加载分支真实类别与任务元数据，根据验证过的定义/名称关联，将候选变体映射回主要任务。

2. 从安装套件解析运行索引，用任务定义、类别、目标和状态资源核对一个实例。

3. 按计划固定规则生成最终面板，不通过运行候选来挑选容易案例。

4. 保存变体名、类别、代码/资源版本、状态引用、采样种子及基础任务映射，使面板能够重建。

**应得到的结果:** 独立于性能、任务到变体映射已验证的最终清单。

**如果没有达到预期:** 变体或资源缺失时明确报错并排查，不悄悄替换任务或类别。

**本次完成清单**

- [ ] 提供类别/任务元数据，按实际任务套件名称解析运行 ID，不假设元数据 ID 就是索引。
- [ ] 检查有代表性的相机和布局用例，核实目标物体及目的位置。
- [ ] 按种子 42，为每任务每维度固定十个变体及明确状态/种子引用，不根据已观察成功率选择。

### 3. 验证无扰动参考与开发试验 (3 小时)

**位置：** 运行电脑：渲染无扰动参考和开发试点，执行策略并比较真实状态/控制/评分。

**详细操作步骤**

1. 在鲁棒性后端用固定原任务及状态构造无扰动参考，不与未标记的基础后端运行直接比较。

2. 为各维度选择独立开发试验，执行策略前先检查图像。

3. 相机试验比较物理状态及应不变的任务部分，布局试验明确指出预期物体/状态变化。

4. 保持同一策略、处理和控制约定，验证请求目标评分；意外后端差异保持可见，不混成相机效应。

**应得到的结果:** 能够检查、能区分预期及意外变化的试验/参考配对。

**如果没有达到预期:** 无扰动参考在分支无法加载时，先解决任务/资源集成，再报告扰动下降。

**本次完成清单**

- [ ] 在鲁棒性后端中，使用固定的原任务定义和状态构建计划中的无扰动参考回合。
- [ ] 为两个扰动维度运行独立开发试验，这些试验用例不得进入最终留出面板。
- [ ] 比较相机图像、物理状态、观测映射、评分和控制设置，混合结果前先排查意外后端差异。

### 4. 诊断扰动并记录结论 (2 小时)

**位置：** 编码电脑：独立诊断返回试点/参考产物；任何受控后续检查在目标执行。

**详细操作步骤**

1. 选择一个开发相机或布局失败。

2. 逐项比较参考与扰动的初始状态、图像、首次预测、后续执行动作和原生谓词。

3. 提出视觉定位、物理抓取难度或流水线/后端不匹配等具体假设，指出区分证据。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 有证据的扰动诊断，而不只给模型贴脆弱标签。

**如果没有达到预期:** 物理状态未变化时，不把相机裁剪变化称为物体位移。

**本次完成清单**

- [ ] 用状态、图像、动作和视频，将一个开发扰动与合适的无扰动参考比较。
- [ ] 提出影响行为的原因，并指出由后端或评分器造成的替代解释。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 审查最终鲁棒性面板 (2 小时)

**位置：** 编码电脑：审查返回最终数量和后端标签。运行电脑：确认基础环境仍正常。

**详细操作步骤**

1. 按主要任务和维度统计最终用例，核对变体/状态唯一标识及计划面板。

2. 分别审查无扰动参考，确认后续三个策略使用完全相同用例定义。

3. 检查所有产物路径和汇总保留后端/类别标识，即便任务名与基础 LIBERO 一样。

4. 保存开发证据，第 10 周前不获取最终面板结果，所有路径更改后重检基础环境。

**应得到的结果:** 完整冻结的鲁棒性清单，以及与基础评估隔离的证据。

**如果没有达到预期:** 数量不符时修正元数据解析，不在事后缩减预期覆盖。

**本次完成清单**

- [ ] 验证冻结面板对每个策略包含八十个扰动用例和八十个参考用例，映射可找回且无重复。
- [ ] 确认配置分支后基础 LIBERO 开发仍能运行，结果标签保留后端标识。
- [ ] 准备完成覆盖和分维度汇总，不把开发试验当成完整 LIBERO-plus 基准。
