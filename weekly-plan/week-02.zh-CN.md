理解目标：

- 用一轮循环讲清观测/指令如何产生解码七维动作及下一观测。
- 区分策略步调用、生成新动作块及实际动作，解释队列重置与只解码一次。
- 结合真实轨迹解释成功、超时、终止事件、基础设施错误及资源清理。

## 准备与学习

- 检查固定版本策略的重置与动作选择方法，以及仿真器的重置、步进、成功和终止行为。
- 理解归一化模型动作、解码后的控制动作与控制器坐标约定之间的区别。
- 阅读动作队列实现，确认何时生成新动作块、何时复用已有动作。

## 实现任务

以下条目明确本周代码及文档交付。现有源码按需完善或扩展；未来组件在真正实现前保持计划状态。实验参数仍以链接的实施计划为准。

1. **单回合输入与结果。** 定义运行时校验的单任务回合输入，包含明确指令、状态引用、策略种子和回合上限。返回强类型结果，含停止原因、请求目标结果、步数/计数、耗时及产物引用，区分真实任务失败、超时、环境终止和基础设施错误。
2. **完整外层循环。** 使用已有连接层实现单个同步回合生命周期：恢复/重置、清空策略/处理器、准备观测和显式指令、经受支持队列选择下一动作、只解码一次、校验、步进及记录下一观测。执行设置遵循检查点约定，不复制上游模型内部逻辑。
3. **动作块及动作计数。** 分别统计策略步调用、新动作块生成和仿真动作执行，记录队列复用，并关联预测块与其实际执行动作。插入记录不得请求额外预测、推进随机数或改变动作选择。
4. **对齐轨迹与视频。** 增加逐步记录，覆盖原始观测、处理后输入摘要、准确指令、动作块/动作标识、解码命令、谓词/结果信号和帧索引。保留时间及顺序，使一帧视频能追踪到对应动作/观测；压缩轨迹随回合结果保存。
5. **执行入口与清理。** 提供单回合命令，明确配置、用例/资源及输出路径。昂贵资源分配前拒绝已有输出标识和无效输入。正常和错误退出均关闭仿真/视频资源，保留原始上下文异常及部分诊断，不把中断回合标为完成。
6. **真实集成与说明。** 先执行短路径检查，再运行试点回合，用真实动作块边界核对计数，并检查预处理/解码及最终观测。在代码指南说明循环函数、记录字段、动作缓存流、停止决策及资源生命周期，提供实际保存回合的完整追踪。

## 分次任务

### 1. 编码前先明确单回合流程 (2 小时)

**位置：** 编码电脑：编写伪代码并检查连接层/源码约定。真实步进检查使用返回的第 1 周证据或在目标执行。

**详细操作步骤**

1. 用自然语言写出回合生命周期，从任务/状态选择到重置、预测、步进、结果记录和资源释放。

2. 逐项指出连接层调用、真实返回类型和循环必须保存的数据，区分新观测与处理后的模型批次。

3. 分别定义停止情况：请求目标成功、明确步数上限、环境终止事件和基础设施异常，不合并成一个布尔值。

4. 审查生命周期及接口，解决约定不清的问题，在第 2 次任务实现完整循环。

**应得到的结果:** 用于完整实现循环的伪代码和输入输出图。

**如果没有达到预期:** 若说不清谁返回成功、哪个函数解码动作，先追踪这两处调用。

**本次完成清单**

- [ ] 编写伪代码，覆盖环境重置、策略重置、观测准备、指令传入、动作选择、步进、评分和资源关闭。
- [ ] 检查真实步进返回值，区分任务成功、回合终止、超时与执行异常。
- [ ] 审查伪代码及连接层约定，并在第 2 次任务实现完整循环。

### 2. 实现完整回合循环 (3 小时)

**位置：** 编码电脑：实现完整循环。运行电脑：第 1 周门槛通过后执行短步进和有界回合检查。

**详细操作步骤**

1. 编写首版，只使用一个环境、一个策略、一条指令和一个明确开发用例。

2. 重置环境和策略，处理一条观测，通过受支持策略接口请求动作，只解码一次，再按正确形状传给仿真器。

3. 先运行足够检查该路径的少量步骤，再完成有界回合；记录前一步结果后再使用下一观测。

4. 在选定步骤检查真实词元、状态形状、解码动作和仿真结果，与第 1 周约定比较。

**应得到的结果:** 实现且能逐步检查状态变化的有界循环。

**如果没有达到预期:** 机器人运动错误时，确认只解码一次，并区分相对末端控制与关节命令。

**本次完成清单**

- [ ] 使用成熟 LeRobot 接口和约定的检查点执行设置实现循环，首版仅支持一个任务和一个回合。
- [ ] 用真实张量梳理一次迭代，包括实际传入分词器的指令，以及发送给环境的七维动作。
- [ ] 以明确步数上限运行一个开发回合，验证开始时已经重置策略状态和动作队列。

### 3. 增加证据并排查集成问题 (3 小时)

**位置：** 编码电脑：集成记录并检查日志。运行电脑：生成三个真实试点轨迹/视频并复现集成错误。

**详细操作步骤**

1. 围绕已有循环接入记录，保持步号及画面、观测、预测动作块和执行动作的对应关系。

2. 标记动作来自新预测还是已有队列，模型输出数量与执行动作数量不必相等。

3. 按记录设置运行试点回合，保留失败轨迹，在视频中检查接触、抓取和放置过程。

4. 提出模型修改前，先把一次成功或失败追溯到动作解码及状态构造。

**应得到的结果:** 视频、预测、动作对齐，且结果标签诚实的试点轨迹。

**如果没有达到预期:** 若视频和状态对应不同步，先修复记录对齐再解释失败。

**本次完成清单**

- [ ] 围绕回合循环接入视频和轨迹写入，保留原始观测、预测、执行动作及完成信息。
- [ ] 如果行为异常失败，检查动作解码、图像朝向、特征映射、状态构建和相对控制。
- [ ] 为试点任务保存三个开发回合，诚实分类观察到的结果，不假设此时一定已有成功视频。

### 4. 修改循环并记录结论 (2 小时)

**位置：** 编码电脑：实现并验证计数并预测数量。迁移改动，在目标执行短回合，再核对返回轨迹。

**详细操作步骤**

1. 沿真实公开调用路径增加策略步调用、新动作块生成及仿真动作执行计数。

2. 阅读固定源码队列条件，明确各计数含义，不把每次 `select_action` 都视为一次新模型预测。

3. 运行短开发回合，手工对照记录的动作块边界核对计数。

4. 审查证据及最强替代解释，修正已定位根因，重跑受影响检查，在对应 `doc/` 双语文档中记录理由。

**应得到的结果:** 名称与实际测量事件一致、由手工轨迹核验的计数。

**如果没有达到预期:** 若统计代码改变采样或额外消耗随机数，移除副作用，不为统计再调用一次策略。

**本次完成清单**

- [ ] 为循环增加推理调用次数和已执行动作数的计数。
- [ ] 预测动作分块执行时两个计数为何不同，再用真实轨迹验证解释。
- [ ] 核实推理及修正，重跑受影响检查，更新双语设计/代码说明及证据引用。

### 5. 解释回合并准备重置实验 (2 小时)

**位置：** 编码电脑：解释返回轨迹并准备重置用例。运行电脑：验证正常/错误路径的资源释放。

**详细操作步骤**

1. 选取具体一帧，讲解其原始观测、处理输入、队列/预测动作、解码命令和下一观测。

2. 验证正常结束与真实开发错误都会释放资源，并保留明确结果或错误记录。

3. 简述即便循环技术上正确，任务为何仍可能失败。

4. 列出下周匹配重置需要控制的仿真状态、策略队列/缓存、随机数和预处理设置。

**应得到的结果:** 完整回合解释，以及下一周必须控制的状态清单。

**如果没有达到预期:** 若终止事件暗中触发再次重置或丢失最终观测，不能宣称流水线可靠。

**本次完成清单**

- [ ] 结合视频和轨迹，解释某条具体指令如何经过一次动作块预测转化为运动。
- [ ] 确认正常结束及真实开发故障后资源都能关闭，并保留有用的错误上下文。
- [ ] 列出第 3 周对照所需控制的仿真器状态、随机数状态和策略缓存。
